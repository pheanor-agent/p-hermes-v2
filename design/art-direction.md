# p-hermes 강의 아트 디렉션과 화면 연출 설계

2026-09-10 · 디자인 설계 1 · 제작 전

[6편 강의 상세 설계](course-plan.md)의 키워드·72개 학습 장면·시간 배분을 유지하고, 실제 화면에서 무엇을 어떻게 보여줄지 정의한다. 이 문서의 콘셉트 보드는 분위기와 구성을 검토하는 이미지이며, 실제 실행 증거나 완성 슬라이드는 아니다. 최종 제목·라벨·수치·코드·기술 도해는 읽고 수정할 수 있는 발표 요소로 다시 제작한다.

## 1. 전체 인상

**기술 다큐멘터리처럼 중요한 순간을 크게 보여주고, 정교한 기술 도해로 그 이유를 설명한다.**

첫 화면에서 p-hermes가 에이전트 시스템에 관한 강의라는 것을 알 수 있어야 한다. 전체·작업·지식·카탈로그에서는 실제 책임·기록·값·구조가 화면의 주인공이다. 이미지·영상 강의에서는 시각 결과물이 크게 등장한다. LUMA 제품 이미지는 이 두 분야와 짧은 통합 사례에 사용한다.

여섯 강의는 서체·색의 의미·여백·정렬을 공유한다. 각 강의의 인상은 다른 장식 테마보다, 다루는 정보의 형태에서 만든다. 작업은 상태가 바뀌는 순간, 지식은 문서와 검색 결과, 카탈로그는 비교와 연결, 이미지는 화면의 공간, 영상은 재생과 시간이다.

재미는 예상한 결과와 관찰한 결과를 비교하고, 작은 차이의 이유를 알아내며, 배운 개념으로 다음 결과를 맞혀 보는 데서 만든다. 여기에 큰 이미지, 읽기 쉬운 글자, 정밀한 배치와 짧은 동작으로 시각적 만족을 더한다.

## 2. 공통 디자인 규격

### 2.1 색과 재질

| 역할 | 색 | 적용 |
|---|---|---|
| 집중 화면 | Midnight `#121D34` | 도입, 장 전환, 소수 값의 극적인 비교, 영상 주변 |
| 설명 화면 | Ivory `#F6F4ED` | 구조, 비교표, 코드, 단계 설명 |
| 밝은 화면 글자 | Ink `#19253B` | 제목·본문·주요 숫자 |
| 어두운 화면 글자 | Ivory `#F6F4ED` | 제목·주요 숫자·라벨 |
| 현재 읽는 대상 | Cobalt `#315BE7` / 어두운 배경에서는 `#BDD0FF` | 현재 입력, 활성 연결, 반영된 값 |
| 차이·확인 지점 | Amber `#A94F1D` / 어두운 배경에서는 `#F0B05C` | 불일치, 거부, 살펴볼 영역 |
| 보조 설명 | Slate `#58677B` / 어두운 배경에서는 `#B8C6DC` | 부차적 라벨·설명 |

배경은 매끈한 단색이다. 사진은 실제 빛과 재질이 느껴지는 자산으로 준비한다. 화면 전체의 그라데이션·광선·유리 효과를 기본 장식으로 사용하지 않는다. 주제마다 무조건 다른 색을 배정하지 않고, 같은 의미에는 같은 강조색을 쓴다. 색과 함께 `반영`, `거부`, `변경` 같은 짧은 라벨을 표시한다.

### 2.2 글자와 정렬

기준은 1920×1080, 16:9다. 좌우 여백 120px, 위 80–100px, 아래 70–80px를 출발점으로 한다. 편집을 위한 내부 기준은 12열, 열 사이 24px이며 실제 화면에 격자선을 노출하지 않는다. 사진과 영상은 의도한 장면에서 가장자리까지 넓힌다.

| 요소 | 시작 규격 | 표현 |
|---|---|---|
| 도입·주제 제목 | 104–128px, 굵게 | 보통 한두 줄. 핵심 주제가 먼저 읽히도록 배치 |
| 설명 화면 제목 | 72–88px | 같은 왼쪽 기준선. 필요한 경우 결과 중심 제목 |
| 처음 정의 | 44–52px | 키워드 아래 짧은 한 문장 |
| 핵심 값 | 140–220px | 리비전·버전 등 그 값이 주제일 때 크게 사용 |
| 도해 라벨·코드 | 36–44px | 대상 가까이에 붙이고 멀리서 읽을 수 있게 유지 |
| 출처·보조 정보 | 24–28px | 판단에 필요한 정보만 표시. 나머지는 노트 |

한글은 Noto Sans KR 계열의 일관된 형태와 굵기를 기준으로 한다. 코드와 필드명은 식별이 쉬운 고정폭 서체를 쓴다. 발표 자산으로 배포할 실제 폰트는 사용 권리와 한글 글리프를 확인한다. 제목과 정의를 둘 다 길게 쓰지 않는다. 중요한 코드가 많으면 여러 화면으로 나누고 4–6줄씩 읽는다.

## 3. 화면의 세 가지 호흡

| 상태 | 청중에게 주는 역할 | 화면 구성 | 넘어가는 조건 |
|---|---|---|---|
| 집중 | 지금 무엇을 볼지 분명히 한다 | 강한 명암 대비, 큰 단어·숫자·결과 하나 | 볼 대상을 소개한 뒤 설명이 필요해질 때 |
| 탐색 | 구조와 차이를 직접 읽는다 | 밝은 배경, 넓은 도해·비교·입출력 | 원인과 결과가 연결됐을 때 |
| 체험 | 실제 결과를 보고 판단한다 | 큰 이미지·영상·실행 출력 | 관찰한 차이를 개념으로 정리할 때 |

밝고 어두운 화면을 번갈아 넣는 규칙은 두지 않는다. 중요한 전환에서 화면의 면적과 밀도를 바꾼다. 동일한 객체가 다음 장면에서도 필요하면 위치·모양·이름을 유지한다. 화면이 바뀌어도 청중이 다시 찾는 비용을 줄인다.

키워드 역시 한 가지 판형으로 반복하지 않는다. 리비전은 큰 숫자, 인덱스는 저장과 검색의 관계, 구도는 사진의 여백, 연속성은 두 경계 프레임과 함께 처음 정의한다. 용어의 모습이 기억할 메커니즘과 연결되도록 한다.

## 4. 여섯 강의의 대표 화면

아래 장면은 모두 기존 상세 설계의 ID와 연결된다. 도입용 장식만 먼저 만드는 일을 피하도록, 각각 다른 제작 난도를 가진 화면을 선택했다.

### D01 전체 — 구조가 펼쳐지는 화면 / O02

**화면:** 짙은 남색. 왼쪽 위에 `에이전트의 구조`를 크게 놓는다. 오른쪽과 아래에 작업·지식·카탈로그의 책임을 보여주는 정렬된 관계도, 그 아래 이미지·영상의 제작 책임을 배치한다. 전체 제목보다 노드가 더 눈에 띄는 복잡한 네트워크를 만들지 않는다.

**진행:** 처음에는 역할 이름과 공통 기반만 보여준다. 발표자가 문서 검토 작업을 설명하면 관련 책임을 하나씩 강조한다. 마지막에 이미지·영상으로 적용 범위를 넓힌다. 다섯 분야를 반드시 순서대로 통과하는 실행선은 그리지 않는다.

**흥미의 지점:** 보이지 않던 시스템이 한 장의 관계로 드러난다. 청중은 “지금 어떤 책임이 필요한가”를 짚고 해당 부분이 확대되는 모습을 본다.

**다음 연결:** 선택한 작업의 위치를 유지한 채 상태 값으로 확대한다. 첫 지도는 회상 장면에서도 같은 배열로 돌아온다.

### D02 작업 — 두 수정과 하나의 현재 값 / T04

**화면:** 밝은 배경. 현재 상태 번호를 중앙에 180px 안팎으로 크게 놓고, 좌우의 A·B가 읽은 번호를 같은 축에 정렬한다. 인물 일러스트나 게임 캐릭터 대신 요청과 번호 자체를 보여준다.

**진행:** A·B 모두 `7`을 읽는다. A의 수정이 반영되면 중앙만 `8`로 바뀐다. B의 `7`은 그대로 남는다. 결과 영역을 비운 채 10–15초 생각할 시간을 주고, `요청 7 / 현재 8`의 불일치를 호박색과 밑줄로 공개한다.

**흥미의 지점:** 두 요청이 똑같아 보였는데 시점에 따라 결과가 달라진다. 큰 숫자의 변화와 짧은 멈춤으로 결과를 기다리게 한다. 반영·거부 결과가 나타나면 바로 비교 규칙을 설명한다.

**다음 연결:** 번호의 두 위치를 실제 `revision` 비교 코드와 출력의 위치에 대응시킨다. 거부 연출에 경고음이나 흔들림을 덧붙이지 않는다.

### D03 지식 — 남아 있는 기록과 달라진 검색 / K09

**화면:** 밝은 배경. 왼쪽에는 문서 한 개를 크게, 오른쪽에는 실제 검색 결과 중 필요한 행만 넓게 배치한다. `기록`과 `검색` 두 라벨로 역할을 구분한다. 브라우저 전체를 작게 축소해 넣지 않는다.

**진행:** 문서가 현재 검색에 포함된 상태를 먼저 본다. 퇴역 후 같은 검색을 실행하면 결과 행이 빠지지만 왼쪽 기록은 남는다. 문서를 삭제하거나 불태우는 비유는 쓰지 않는다. 실제 녹화에서 DB 기록과 반환 결과를 각각 확인한다.

**흥미의 지점:** “검색에서 사라졌다”와 “기록이 삭제됐다”가 다르다는 사실을 눈으로 발견한다. 효과보다 남아 있는 문서의 존재가 강조점이다.

**다음 연결:** 같은 문서를 새 판본으로 바꾸는 질문으로 넘어가며 갱신·퇴역의 관계를 복기한다.

### D04 카탈로그 — 같은 이름 아래 달라진 내용 / C06

**화면:** 어두운 배경. 동일한 `v2.0` 두 개를 크게, 같은 기준선에 배치한다. 아래에는 비교할 필드 서너 개만 두고 차이가 있는 한 줄에 호박색 밑줄을 붙인다. 실제 해시 전체를 작은 장식 텍스트로 채우지 않는다.

**진행:** 처음에는 버전 이름만 보여준다. 내용을 펼치면 한 필드의 차이가 드러난다. 청중이 다음 실행에서 같은 구성을 쓴다고 말할 수 있는지 판단한 뒤 실제 digest 비교 결과를 읽는다. 해시를 줄여 표시하면 `앞부분만 표시`라고 적고 전체는 노트에 둔다.

**흥미의 지점:** 같아 보이는 이름과 다른 내용의 불일치가 시선을 붙잡는다. “틀린 그림 찾기”의 관찰을 버전 고정과 내용 고정의 구분으로 연결한다.

**다음 연결:** 고정된 템플릿을 그대로 둔 상태에서 입력값이 어디로 들어가는지 확대한다.

### D05 이미지 — 여백이 기능하는 큰 사진 / I03

**화면:** 청록색 LUMA 램프를 실제 재질과 부드러운 빛이 보이도록 촬영하거나 교육용 이미지로 제작한다. 제품은 화면의 약 45–55% 영역에 두고, 문구가 들어갈 영역을 충분히 남긴다. 제목은 그 여백 안에 자연스럽게 들어간다. 정확한 비율은 제품과 문구 길이에 맞춰 조정한다.

**진행:** 원본 사진을 크게 보여주고, 문구 영역과 제품 윤곽에만 얇은 안내선을 켠다. 안내선을 끄면 완성된 이미지로 돌아온다. 비교 장면에서는 제품 위치만 다른 두 결과를 같은 축척으로 보여준다. 목적에 따라 전후 전환이나 좌우 비교 중 하나를 선택한다.

**흥미의 지점:** 한 번의 표시로 “좋아 보인다”는 인상이 구체적인 공간 조건으로 읽힌다. 청중이 고른 구성의 이유가 명세와 프롬프트의 설명이 된다.

**다음 연결:** 강조한 문구 공간 조건을 다음 화면의 명세·프롬프트 항목에 같은 이름으로 붙인다.

### D06 영상 — 경계에서 드러나는 연속성 / V06

**화면:** 상단 대부분을 실제 영상에 주고 아래 15–20%에 짧은 시간선을 둔다. 경계 비교에서는 재생 영역을 같은 크기의 두 프레임으로 바꾼다. 장면 전체에 필름 구멍·플레이어 장식·가짜 파형을 붙이지 않는다.

**진행:** 8–15초의 교육용 영상을 한 번 재생한다. 샷 경계에 재생 위치를 멈추고 경계 전후 프레임을 펼친다. 위치·빛·움직임 중 설명할 차이 하나를 강조한다. 다시 재생하며 눈으로 발견한 차이가 시간 속에서 어떻게 느껴지는지 확인한다.

**흥미의 지점:** 처음에는 막연히 어색했던 부분을 재생과 정지의 전환으로 찾아낸다. 청중이 편집자의 시선으로 영상을 다시 보게 한다.

**다음 연결:** 해당 샷만 수정하면 무엇을 다시 볼지 묻고, 참조·시간선·전체 검수의 영향 범위를 표시한다.

## 5. 움직임의 문법

| 목적 | 동작 | 초기 길이 | 발표자의 멈춤 |
|---|---|---:|---|
| 현재 위치 표시 | 기존 선·라벨의 강조를 옮김 | 180–240ms | 해당 연결을 읽는 동안 유지 |
| 값의 변경 | 같은 위치에서 이전 값과 새 값을 교체 | 200–300ms | 전후를 비교할 시간 확보 |
| 의미 있는 확대 | 기존 대상에서 코드·필드·프레임으로 확대 | 300–450ms | 움직임이 끝난 뒤 설명 |
| 차이 공개 | 차이 영역에 밑줄·명확한 라벨 표시 | 150–220ms | 청중이 차이를 확인한 뒤 이유 설명 |
| 결과 대기 | 화면은 정지, 결과 영역만 비워 둠 | 자동 타이머 없음 | 보통 10–15초 생각할 시간 |
| 영상 검토 | 실제 시간 재생, 경계 정지, 필요 시 느린 재생 | 원본 길이에 따름 | 정지 프레임에서 설명 |

이 수치는 초기 연출값이며 청중 반응이 보장되는 값이 아니다. 한 번에 하나의 의미 있는 변화만 활성화한다. 일반 단계는 발표자의 키 입력으로 진행한다. 축소 동작 설정에서는 이동을 생략하고 최종 비교 상태를 바로 보여준다. PDF에는 원인과 최종 결과가 함께 남도록 정적 구성을 별도로 만든다.

키워드를 화면 밖에서 날아오게 하거나 글자마다 튀게 하지 않는다. 중요한 단어의 등장만으로도 충분한 장면에서는 움직임 없이 크기·정렬·여백으로 집중시킨다.

## 6. 재미를 만드는 질문과 공개의 순서

| 경험 | 쓰는 장면 | 실제 질문 | 답이 다음 설명에 쓰이는 방식 |
|---|---|---|---|
| 발견 | K09 | 검색에서 빠졌다면 기록은 어디에 있을까 | 보존과 재사용의 구분 |
| 예측 | T04 | 두 번째 수정은 반영될까 | 리비전 비교 |
| 불일치 찾기 | C06 | 같은 버전인데 같은 내용인가 | 버전과 해시 |
| 선택 | I03 | 이 문구를 넣을 때 어느 구도가 맞을까 | 명세와 공간 조건 |
| 재관찰 | V06 | 어색했던 순간은 어느 경계였을까 | 연속성과 검수 |
| 자기 적용 | O11 | 내 작업의 이 결정은 어느 책임에 속할까 | 다섯 분야의 역할 지도 |

새로운 용어를 설명하지 않은 채 정답을 요구하지 않는다. 처음에는 관찰할 질문을 던지고, 규칙을 배운 다음 예측하게 한다. 대답은 손들기·짧은 선택·혼자 생각하기로 충분하다. 인터넷 투표 서비스에 의존하지 않는다. 질문이 이어지는 구간에는 다음 장면을 시연이나 조용한 비교로 바꾼다. 웃음을 위한 별도의 이야기나 유행 밈은 이번 기본 구성에 넣지 않는다.

## 7. 처음 10분으로 확인할 연속 시안

T04 전체 6분과 T05 앞 4분을 이어, 디자인이 설명의 흐름을 감당하는지 확인한다. 강의 시간표를 바꾸는 것이 아니라 제작 검토용 발췌 구간이다.

| 구간 | 화면 변화 | 확인할 것 |
|---|---|---|
| 0:00–0:40 | 큰 리비전 제목과 번호의 정의 | 단어와 대상을 연결하는가 |
| 0:40–2:20 | 같은 번호를 읽은 두 요청, A 반영 뒤 현재 번호 변경 | 시점과 객체의 위치가 분명한가 |
| 2:20–2:50 | 결과 공개 전 정지 | 질문이 자연스럽고 기다림이 어색하지 않은가 |
| 2:50–4:00 | 요청과 현재 값의 차이, 거부 결과 | 무엇이 달라졌는지 바로 보이는가 |
| 4:00–5:10 | 핵심 코드와 오류 출력 대응 | 글자가 충분히 크고 시각 설명과 연결되는가 |
| 5:10–6:00 | 최신 번호를 가진 요청의 변형 질문 | 다음 조건을 배울 이유가 생기는가 |
| 6:00–8:00 | 실제 공개 Store의 읽기·변경·거부 출력 | 설명용 그림과 실제 동작의 대응이 정확한가 |
| 8:00–10:00 | 안전한 실습 입력의 번호 하나 변경과 비교 | 시연을 본 뒤 개념을 적용할 수 있는가 |

평가는 정지 화면과 연속 발표를 함께 본다. 작은 전체 보기에서는 판형·밀도의 리듬을, 실제 크기에서는 읽기 순서와 가독성을, 연속 재생에서는 멈춤·질문·전환을 확인한다. 시안의 실행값과 영상·음성이 준비되지 않은 상태를 리허설 완료라고 기록하지 않는다.

## 8. 이미지·영상의 제작 지시

LUMA 이미지는 제품 전체, 디테일, 문구 배치, 샷 경계가 각기 다른 학습 목적을 갖도록 준비한다. 모든 장에서 동일한 제품 이미지를 배경으로 반복하지 않는다. 비교에 필요한 경우 제품의 형태·색·카메라 조건을 의도적으로 유지하고 변경한 조건을 기록한다.

| 자산 | 제작 지시 | 피할 오해 |
|---|---|---|
| 구도 사진 | 청록색 무광 램프, 밝은 중성 공간, 실제 재질, 문구가 놓일 여백, 같은 축척의 전후 비교 | 생성된 교육용 장면을 실제 p-hermes 생성 실행으로 표시하지 않음 |
| 경계 영상 | 동일 제품의 두 샷에서 위치·빛·움직임 중 한 차이를 관찰 가능하게 제작 | 모든 요소를 한꺼번에 바꿔 원인을 흐리지 않음 |
| 편집 A/B | 같은 샷 원본을 사용하고 길이 배분만 변경 | 다른 원본을 비교하면서 타이밍 효과라고 주장하지 않음 |
| 코드 녹화 | 필요한 입력과 출력만, 읽을 부분을 실제 크기로 캡처 | 전체 터미널을 작게 넣거나 존재하지 않는 결과를 연출하지 않음 |

최종 이미지와 영상에는 출처·권리·제작 조건·실제 실행 여부를 기록한다. 자료가 준비되지 않으면 해당 장면을 제작 대기로 표시하고, 설명용 정지 그림을 완성 영상처럼 보고하지 않는다. 영상에는 자막·전사와 대표 프레임 대체물을 준비한다.

## 9. 72개 학습 장면에 디자인을 적용하는 방법

각 장면의 화면 유형, 첫 시선, 공개 동작, 다음 장면에 유지할 요소를 [72개 장면의 시각 연출 명세](visual-cues.json)에 지정했다. 같은 주제의 모든 장면을 한 판형으로 복제하지 않는다. 예를 들어 작업 강의에서도 상태 지도, 번호 비교, 코드 확대, 실행 시간선, DB 결과를 내용에 맞게 번갈아 쓴다.

전체 보기에서 같은 판형이 길게 이어지면 다음 두 가지를 확인한다. 내용 자체를 묶는 편이 나은지, 또는 같은 내용을 다른 매체로 표현해야 이해가 쉬운지 판단한다. 다양성을 만들기 위해 무관한 그림을 추가하지 않는다.

제작 명세에는 기존 `scene_id`, `keyword_ids`, `visual_asset_ids`에 `visual_mode`, `composition`, `first_focus`, `motion_cues`, `hold_points`, `continuity_anchor`, `static_state`를 추가한다. 기획 문서에서 말한 연출이 실제 슬라이드와 PDF까지 추적되도록 한다.

## 10. 제작 판단 기준

| 기준 | 검토 질문 | 수정 방향 |
|---|---|---|
| 첫인상 | 이 화면의 주제가 한눈에 드러나는가 | 제목·시각 대상·부차 정보의 크기를 다시 배분 |
| 완성도 | 정렬·여백·서체·사진의 질이 일관되는가 | 기준선을 맞추고 자산을 교체하거나 다시 제작 |
| 흥미 | 다음에 드러날 차이나 결과가 있는가 | 원인·관찰 질문·공개 순서를 재편 |
| 이해 | 움직임이 끝난 뒤 변화 이유를 설명할 수 있는가 | 움직이는 대상을 줄이고 라벨을 가까이 배치 |
| 기술 깊이 | 실제 값과 코드가 설명에 필요한 크기로 보이는가 | 내용을 나눠 보여주고 결과와 직접 대응 |
| 연속성 | 장이 넘어가도 같은 대상과 키워드를 찾을 수 있는가 | 위치·명칭·색 의미를 유지 |
| 시간 | 멈춤과 시연을 포함해 설명이 자연스럽게 끝나는가 | 효과를 빠르게 돌리기보다 장면을 편집 |

개별 시안 6개와 10분 연속 구간을 이 기준으로 검토한다. 실제 청중이 있으면 관찰한 핵심과 예측 이유를 받아 수정한다. 시안 이미지의 미감, 구현된 슬라이드의 동작, 실제 학습 효과는 각각 다른 단계의 검토 결과로 기록한다.

## 11. 이번 설계의 산출물

- 본 문서: 화면 규격, 주제별 대표 연출 6개, 움직임 규칙, 질문과 공개의 연결, 10분 연속 시안 구성.
- [대표 화면 콘셉트 보드](art-board.png): 기본 내장 ImageGen으로 생성·수정한 정적 방향 검토 자료. 색·위계·사진과 도해의 구성을 검토했다. [생성·수정 프롬프트와 검토 기록](art-board-prompts.json)을 함께 보존한다.
- [72개 장면의 시각 연출 명세](visual-cues.json): 각 장면의 첫 시선·화면 유형·동작·이어지는 대상을 지정한 제작용 자료.
- [기존 강의 설계](course-plan.md): 핵심 용어 정의·72개 학습 장면·시간 배분의 기준.

아직 실제 여섯 강의나 발표용 애니메이션·영상 패키지는 제작하지 않았다. 이번 요청에서는 그 결과물을 구체적으로 만들 수 있는 디자인과 연출을 설계한다.

콘셉트 보드의 개별 패널은 완성된 16:9 레이아웃이 아니다. 실제 슬라이드는 1920×1080에서 다시 구성하고, 생성된 연결선·예시 값·텍스트를 검증된 편집 요소로 대체한다. 특히 리비전의 단계별 수락·거부와 영상 경계 차이는 실제 실행·미디어로 확인한다.
