작업 흐름을 찾아 쓰기

강의 02의 개념 설명을 반복하지 않고, 현재 계약·단계·검사·적용 경계를 원본 파일에서 확인합니다.

1. 두 가지 경로

새 요청은 simple 또는 light 중 하나로 처리됩니다. 등급은 분류기(orchestration/classify-input.sh·classify-tier.py)가 정합니다.

  • simple: JOB 없이 요청서·대화 범위에서 바로 수행합니다. 지휘 에이전트가 보낸 요청서(헤더 created_by: orchestrator|heartbeat)는 이미 승인된 실행 지시라 simple로 분류됩니다.
  • light: 기록이 필요한 작업입니다. 실제로 그 일을 하는 에이전트가 light JOB을 만들고 네 단계를 지납니다.

JOB을 만드는 기준(POLICY (f)): 운영 파일을 바꾸거나, 여러 요청에 걸치거나, 나중에 근거로 다시 볼 결정이 있을 때입니다. 그 밖의 조회·일회성 생성·작은 수정은 요청·응답 이력과 orchestration/records/manager-actions.md 한 줄로 충분합니다.

2. 단계 계약

정본은 core/skills/custom/workflow/v2/contract.yaml입니다. light 단계는 아래 순서이며 계약은 목적, 입력, 필수·선택 제출물, 통과 조건, 검사, 다음 단계를 정합니다.

  1. request: 범위와 완료 조건 고정; 필수 request.md.
  2. execution: 허용 경계 안에서 수행; 필수 execution.md, 산출물은 요청에 따라.
  3. verification: 테스트와 실물 대조; 필수 verification.md.
  4. done: 근거와 결과 정합 확인; 필수 result.md.

실제 안내 파일: steps/light-request/SKILL.md, steps/execution/SKILL.md, steps/verification/SKILL.md, steps/complete/SKILL.md. 저장소 README와 계약 원문을 함께 읽어 버전 차이를 확인하세요.

3. 실행 및 검사 명령

신규 light JOB 생성과 단계 전이는 다음 형태입니다. light는 측정 가능한 목표(-g)가 필수입니다.

bash <Hermes 설치 경로>/core/scripts/create-job.sh -y --tier light 개선 "작업 제목" -g "측정 가능한 목표와 완료 조건"
python3 <Hermes 설치 경로>/core/scripts/context_pack.py <JOB>/request.md --out <JOB>/artifacts/context-pack.md
bash <Hermes 설치 경로>/core/skills/custom/workflow/scripts/workflow-gate.sh JOB-XXXX advance

JOB 폴더에는 request.md, approval.md, work-history.md(시간순 결정), artifacts/(분석·초안·로그), execution.md, verification.md, result.md(결과·남은 것·교훈 링크), pre-change/(원본·되돌리기)가 들어갑니다. 각 단계 전이는 gate가 수행하며 누락된 파일·승인 근거는 통과하지 않습니다. 막히면 우회하지 않습니다. 구현은 core/skills/custom/workflow/v2/runner.py, check.sh에서 확인합니다. 이 페이지의 명령은 설명용이며 자동 실행되지 않습니다.

4. 승인 기록

light JOB은 실행 단계 전에 JOB 폴더 approval.md에 두 줄이 있어야 게이트가 통과시킵니다.

approved_by: <승인한 사람>
evidence: <사용자 승인 메시지 ID 또는 원문 인용>

지휘 에이전트는 사용자가 대화에서 승인한 문장을 그대로 인용합니다. 작업 에이전트는 승인이 없으면 지어내지 않고 응답서에 승인 요청을 적은 뒤 멈춥니다(WORKER.md 1절). 영구 삭제·외부 전송·게시·자격증명·보안 설정·POLICY 개정은 반드시 사용자 승인 원문이 있어야 합니다(POLICY (i)).

5. timeout과 terminal 결과

필수 산출 완료 여부를 기준으로 terminal 상태를 사실대로 정합니다.

  • done: 필수 산출이 모두 끝났고 결과가 완료 조건을 만족.
  • partial: 일부 단계만 끝났지만 생성된 산출은 보존하고 남은 일을 기록.
  • failed: 실행 오류로 목표 산출을 완료하지 못함.
  • blocked: 안전 경계·필수 입력·권한 또는 재현 오류로 진행 불가.

timeout이나 실패 때문에 이미 만든 파일을 버리지 않습니다. 완료 여부는 실행 기록과 파일을 다시 읽어 확인하고, 권장 검증이 미완이면 필수 산출과 구분해 보고합니다.

6. 완주와 복구 규칙

  • 완주 우선(POLICY (0)): 쓸 수 있는 결과를 80~90% 완성도로 끝까지 만들고, 남은 부분은 실사용 피드백으로 다듬습니다.
  • partial은 원 목표 + 직전 실패 원인 1줄 + 바꾼 점 1줄 + 남은 항목으로 이어가기 1건, timeout은 한 단계 올리거나 나눕니다(POLICY (a-4)).
  • 같은 goal에서 blocked 2회 또는 partial 3회 연속이면 원인을 한 번 진단하고 진단 기록 전까지 반복하지 않습니다.
