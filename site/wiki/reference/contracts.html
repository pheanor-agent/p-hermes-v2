요청서와 응답서의 약속

요청서에는 목표, 완료 기준, 참조 경로와 금지 범위를 적어 작업의 경계를 분명히 합니다. 응답서는 같은 요청 식별자와 실제 상태를 돌려주고, 산출물과 남은 항목을 밝혀야 합니다. 이 연결 덕분에 결과를 원 요청과 짝지어 다시 확인할 수 있습니다.

요청에서 확인할 것

  • 목표와 완료 기준이 실제로 수행 가능한 말로 적혀 있는지 확인합니다.
  • 참조 경로가 무엇인지, 금지 범위가 어디까지인지 확인합니다.
  • 조건을 바꾸어 재시도하면 새 시도 식별자를 사용하는지 확인합니다.

응답에서 확인할 것

항목확인 기준
request_id응답의 식별자가 원 요청과 같은지
status실제 산출·완료 기준과 맞는 종결 상태인지
산출 경로지정 위치에 파일이 있고 내용을 읽을 수 있는지
남은 항목미완료나 개선점이 숨겨지지 않았는지

종결 상태

상태의미
done완료 기준을 충족
partial일부 산출은 있으나 완료 기준을 충족하지 못함
failed수행 실패
blocked필수 입력·권한 또는 경계 문제로 진행 불가

상태 이름만으로 실제 권한을 제한하지는 않습니다. 완료 보고는 응답서뿐 아니라 요청된 산출물과 검증 근거를 함께 확인해야 합니다. JOB 단계와 필수 파일은 작업 흐름 참조에서 별도로 다룹니다.

Hermes 엔진·로컬 운영 확장·p-hermes

강의의 에이전트·작업 흐름·지식은 로컬 운영을 읽는 세 층입니다. 아래 표는 각 구성의 제공 범위와 출처를 비교합니다.

대상제공하는 것확인할 출처
Hermes 엔진모델·도구 반복, 세션 저장·맥락 압축, 메모리·스킬, 내장 하위 에이전트 위임, 게이트웨이·cronHermes 공식 구조 문서
사용자 로컬 운영 확장역할별 POLICY·WORKER, 파일 dispatcher, JOB 분류기·게이트, 교훈 기록·가공해당 설치의 운영 정본. 이 사이트는 이를 일반화해 설명합니다.
p-hermes한국어 강의·위키와 독립 파일 전달 참조 구현·테스트공개 저장소. 엔진과 로컬 운영 확장 전체를 설치하지 않습니다.

공개 JSON, 문서 handoff, 로컬 JOB 운영의 차이

같은 파일 handoff 아이디어를 설명하지만, 이들은 같은 형식이나 실행 계층이 아닙니다.

범위실제 계약이 사이트에서 의미하는 것
공개 JSON 참조요청: request_id, goal_id, intent_revision, inputs, acceptance, policy. 응답: request_id, goal_id, intent_revision, status, request_sha256, artifacts 및 선택 result·error.공개 계약 문서 및 참조 코드가 정본. 교육용이고 Hermes 제품 API가 아닙니다.
실제 Markdown handoff요청서와 응답서 문서 형식. 최소 식별 필드는 요청서의 request_id와 응답서의 request_id·status; 본문 요약·산출 경로 등은 사람이 읽는 내용입니다.공개 JSON의 필드 전체를 그대로 요구하지 않습니다. JSON 직렬화·자동 변환이 아니며 동등한 스키마라고 가정하지 않습니다.
로컬 dispatcher·분류기worker_dispatch.py 파일 전달과 분류기의 실행 경로 선택개인 운영 설치의 구성요소이며 공개 저장소에서 제공하지 않습니다. upstream Hermes 설치나 p-hermes clone만으로 생기지 않습니다.
로컬 JOB 게이트workflow-gate.sh와 JOB 계약이 단계·승인 기록·필수 산출을 검사POLICY·WORKER의 권한·기록 절차와 함께 동작하는 별도 운영 확장입니다. 문서에 적힌 로컬 경로·명령은 로컬 설치를 찾기 위한 좌표입니다.

공개 출처와 확인 범위(기준일 2026-10-07): Hermes 공식 문서의 아키텍처, 세션 저장, 맥락 압축, 도구, 메모리, 스킬, 위임, 메시징 게이트웨이, 예약 작업을 엔진 기능의 출처로 확인했습니다. 공개 p-hermes 저장소에서는 orchestrator.py, worker.py, 계약 문서를 확인했습니다. 로컬 확장의 상세는 설치별 정본에만 있으므로 공개 자료가 전체 운영 기능을 제공한다고 일반화하지 않습니다.

공개 구현

파일 handoff의 공개 참조 구현과 테스트는 저장소의 reference/와 tests/에서 확인할 수 있습니다. 이는 설명용 참조 코드이며 실제 운영 시스템 전체의 설치·복제를 뜻하지 않습니다.
