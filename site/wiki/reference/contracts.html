파일 handoff 계약

전체 흐름 속 위치

계약은 지휘 에이전트(오케스트레이터)의 요청과 작업 에이전트(워커)의 응답을 식별자·상태·산출물로 연결합니다.

이 실습은 로컬 교육용 계약입니다. 모든 에이전트 제품이 파일이나 필드를 자동 지원한다고 가정하지 않습니다.

요청

필수 JSON 필드: request_id(불변 시도 식별자), goal_id(목표 식별자), intent_revision(양의 정수), inputs(허용 루트 아래 상대 경로 배열), acceptance(완료 조건), policy(제약 메타데이터 객체). 요청을 바꾸면 새 request_id를 사용합니다. policy 기재만으로 운영체제 접근제어가 생기지 않습니다.

응답

필수 필드: request_id, goal_id, intent_revision, status, request_sha256, artifacts. 선택 필드: result, error. 응답 식별자가 수집 대상과 다르거나 상태가 terminal enum 밖이면 거부합니다.

상태 뜻
done 해당 시도 완료 조건을 충족
partial 산출물을 보존했지만 완료 조건 미충족
failed 보존된 산출물 없이 수행 실패
blocked 입력 검증 또는 정책 경계에서 수행 중단

흐름

원 요청의 보관·이동은 호출자 책임입니다. 입력 경계는 canonical 경로를 검사하지만 실제 프로세스 권한, 파일시스템 권한, 동시 처리 claim/lease까지 대신하지 않습니다. 파일 원자적 기록 역시 큐 잠금 프로토콜이 아닙니다. 이 예제는 표준 라이브러리와 임시 폴더만 사용하며 외부 네트워크·GPU·자격증명을 사용하지 않습니다.

근거 코드: 요청 발행, 요청 처리와 경로 제한, 원자적 파일 기록, 계약 테스트.
