지식 참조와 출처 상태

이 문서는 실제 사용 절차와 확인 가능한 입력·출력 계약을 찾기 위한 참조입니다. 강의 03은 전체 개념 흐름을 설명하고, 이 페이지는 명령·상태·제한을 다룹니다.

1. 범위와 용어

용어이 페이지에서의 의미
검색 후보요청과 관련 있을 수 있어 검색 결과로 반환된 자료. 후보 반환만으로 사실 확인이나 채택이 끝나지 않습니다.
context pack요청 전에 관련 후보의 경로·요약·출처 상태를 묶어 제공하는 참고 자료. 작업 에이전트가 이를 실제로 읽거나 판단에 사용했음을 보증하지 않습니다.
출처 상태본문 확보 여부, 명시된 검증 상태, 기록된 날짜를 별도로 표시한 값입니다.
검토 대기열사람이 확인할 교훈 후보와 검토 상태를 추적하는 목록입니다. 자동 승격 대기열이 아닙니다.

2. context pack 생성

요청서 파일을 입력으로 사용합니다. 기본 검색은 단어 중심 후보 검색입니다. 선택적 재순위가 가능해도 빈 결과를 채워 주거나 전체 요청에 대한 커버리지를 보장하지 않습니다.

python3 <Hermes 설치 경로>/core/scripts/context_pack.py <요청서> [--out <결과파일>] [--stale-days <일수>]

현재 확인된 CLI 인자: 위치 인자 request, 선택 인자 --out, --stale-days(기본 180). 생성 실패는 실패 종류를 담은 pack으로 남길 수 있으므로, 출력 파일만 존재하는지 보지 말고 내용을 읽어야 합니다. 도구가 허용 경로 밖 자료나 비공개·민감 자료를 걸러내더라도, 그 자체가 반환 후보의 정확성을 증명하지는 않습니다.

3. 검색 결과 해석

  • 정밀도: 반환된 후보 중 요청과 관련 있는 비율입니다.
  • 커버리지: 전체 요청 중 답에 필요한 자료를 찾아낸 범위입니다.
  • 두 지표는 구분합니다. 제한된 평가에서 반환 결과가 모두 관련이어도, 많은 요청이 빈 결과라면 검색이 충분하다고 결론내리지 않습니다.
  • 빈 결과와 안전 억제는 검색이 처리하지 못한 경우를 포함할 수 있으므로, 이유를 확인하지 않고 자료가 없다고 단정하지 않습니다.

후보가 없음은 확인 가능한 결과지만, 전체 지식에 자료가 없다는 증명은 아닙니다. 검색 범위·필터·평가 범위를 함께 기록하세요.

4. 출처 상태와 날짜

python3 <Hermes 설치 경로>/core/scripts/knowledge_source_status.py <마크다운-파일> [--stale-days <일수>]

현재 CLI는 파일 경로와 선택적 --stale-days(기본 180)를 받으며 JSON으로 상태를 출력합니다. 판별 항목은 본문 확보 여부(acquired / not_acquired / unknown), 검증 상태(validated / rejected / unverified / unknown), 명시 날짜 및 오래됨 여부입니다.

  • 본문에 유효한 내용이 없으면 본문 상태를 확보되지 않음 또는 미확인으로 구분합니다.
  • 검증 상태는 frontmatter의 명시 필드에서만 판정합니다. 그 외는 unknown입니다.
  • 날짜가 없거나 파싱되지 않으면 날짜와 오래됨 여부는 미확인으로 남깁니다. 파일 수정 시각으로 최신성을 꾸며내지 않습니다.
  • 기준 일수를 넘었다는 표시는 최신성 확인이 필요하다는 뜻이지 내용이 틀렸다는 판정이 아닙니다.

5. 교훈 검토 대기열

python3 <Hermes 설치 경로>/core/scripts/lesson-review-queue.py build
python3 <Hermes 설치 경로>/core/scripts/lesson-review-queue.py validate
python3 <Hermes 설치 경로>/core/scripts/lesson-review-queue.py set <candidate_id> accepted|rejected|promoted|pending

확인된 하위 명령은 build, validate, set입니다. build는 index의 명시적 candidate 행에서 대기 후보를 만들고 이전 검토 상태를 보존합니다. set은 후보 ID와 상태를 지정하며, 검토 상태 변경은 검토일을 기록합니다. promoted는 기록된 상태일 뿐, 정본이나 스킬 파일을 자동 수정하는 동작이 아닙니다. 후보의 채택·반려·승격은 실제 근거를 사람이 검토한 뒤 수행합니다.

6. 요청부터 판단 근거 기록까지

  1. 요청별 context pack을 생성하고 결과 파일을 읽습니다. 생성 실패·빈 결과·후보 반환을 서로 구분합니다.
  2. 검색 후보가 있으면 후보의 원문을 직접 엽니다. 요약이나 인덱스만 원문 근거로 간주하지 않습니다.
  3. 출처·검증 상태·날짜를 확인합니다. 알 수 없는 항목은 unknown으로 유지합니다.
  4. 현재 요청에 적용 가능한 사실인지 판단하고, 실제로 사용한 경로와 이유를 작업 기록에 적습니다.
  5. 교훈 후보는 검토 대기열에서 사람의 결정을 기록합니다. 자동 수집·표시와 정본 채택을 분리합니다.

7. 제한과 운영 상태 읽기

검색 정밀도와 커버리지는 별도 측정입니다. 특정 평가의 점수는 그 평가 범위를 벗어난 전체 성능을 말해 주지 않습니다. 자동 제공은 참고 경로이며 원문 사용을 보증하지 않습니다. 출처 상태의 표시도 사실 진위를 자동 판정하지 않습니다. 파이프라인 일부가 구현됐다는 말과 전체 복구·운영 완료도 구분해야 합니다.

현재 K5 기준으로 context pack 평가에서 요청 다수가 빈 결과로 남았고, 검토 대기열은 제한된 후보만 추적합니다. 이 페이지는 전체 시스템 복구나 검색 성능 개선을 주장하지 않습니다. 미완료 또는 부분 상태는 원 기록의 상태 그대로 읽으세요.

8. 코드·CLI 근거

  • context_pack.py — context pack 생성, 검색 후보 수집·제한, 민감 자료 필터, 출처 상태 결합.
  • knowledge_source_status.py — 마크다운 frontmatter와 본문을 읽는 읽기 전용 출처·최신성 분류기.
  • lesson-review-queue.py — 후보 대기열 작성·상태 기록·스키마 검증.

CLI 사용법은 현재 설치본에서 확인했습니다. 공개 저장소의 clone URL·고정 버전은 예제 코드와 연결된 정본이 확인되지 않아 이 페이지에서 만들지 않습니다.
