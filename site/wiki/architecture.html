구성과 범위

파일 handoff를 이루는 구성요소와 각 요소가 주고받는 파일을 설명합니다. 구성별 책임과 경계를 확인해 공개 참조 코드와 로컬 운영 파일을 구분할 수 있습니다.

아래 로컬 경로는 설치별 좌표를 설명합니다. 전체 범위는 구성별 경계에서 구분합니다.

요소와 파일

표의 로컬 경로는 <로컬 운영 루트>를 기준으로 한 상대 경로입니다. 공개 p-hermes 저장소에 같은 경로가 있다는 뜻은 아닙니다.

한 요청이 지나가는 순서

매니저
  → 등록기: goal/revision을 확인하고 요청서 생성·재사용·대체
  → inbox: <request_id>-request.md
  → dispatcher: 경로·중복 확인, task state/attempt 기록, 워커 실행
  → 워커: 요청 수행, 산출 보존, 응답서 작성
  → outbox: <request_id>-response.md
  → 판정: dispatcher 상태·응답서·산출 경로를 대조해 수용 또는 이어가기

등록 결과의 created, reused, superseded는 각각 새 요청, 기존 요청 재사용, 새 revision/시도로 이전 요청을 대체해 등록했음을 나타냅니다. 등록만으로 자식 프로세스가 실행되지는 않습니다.

상태 파일과 응답서

state.json은 새 상태형 작업의 실행 기록입니다. 예를 들어 queued는 등록 대기, running은 워커 실행, verifying은 응답 확인, succeeded는 실행 완료를 나타냅니다. 실행 중 부분 결과나 복구 대기는 waiting, 실패·차단은 failed로 정산될 수 있습니다. 이 상태는 응답서의 done/partial/failed/blocked와 같은 필드나 상태 체계가 아닙니다. 응답서와 파일 실물을 함께 확인합니다.

Hermes 엔진·로컬 운영·p-hermes 공개 범위

이 사이트는 Hermes 엔진 위의 로컬 운영 확장을 설명하며, 공개 저장소의 소형 파일 전달 참조 구현과 구분합니다.
