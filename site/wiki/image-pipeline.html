이미지 생성 파이프라인 참조

이 페이지는 공개된 오프라인 예제의 인터페이스와 운영상 확인점을 정의한다. 아래 명칭과 데이터 형식은 이 예제 구현에 한정하며, 실제 생성 백엔드의 특정 명령·내부 경로를 뜻하지 않는다.

1. 적용 범위와 공개 안전 경계

예제는 합성 장면 의도를 카탈로그 항목과 결합해 프롬프트를 만들고, 가짜 런타임의 결과 메타데이터를 검사한다. 표준 라이브러리만 사용하며 GPU·모델 파일·네트워크·외부 서비스가 필요 없다. 실제 생성·이미지 품질 판정·게시를 수행하지 않는다.

공개 범위: 합성 입력과 예제 코드만 사용한다. 자격증명, 사용자 경로, 내부 식별자, 실제 카탈로그 또는 생성물을 요청·출력하지 않는다.

2. 카탈로그 권위 모델

JSON 카탈로그에는 이름이 붙은 합성 항목과 기본 스타일·비율이 기록된다. 이 예제에서 파일은 카탈로그 입력의 정본이며 요청이 지정한 카탈로그 이름이 없거나 알 수 없으면 오류로 종료한다. 장면별 주제·행동·장소·카메라·조명·제약은 요청이 권위자다. 카탈로그의 기본값은 요청에서 별도로 지정한 값보다 우선하지 않는다.

입력권위사용 시점
카탈로그 항목합성 catalog.json선택한 스타일·기본 비율
장면 의도request.json주제·행동·장소·카메라·조명·제약
가짜 런타임 응답실행 중 만들어진 메타데이터상태·요청 식별자·프롬프트 해시 기록

기본값 결합 뒤 최종 출력의 값을 확인한다. 설정이 있다는 사실만으로 실제 런타임이 해당 값을 적용했다고 추정하지 않는다.

3. 프롬프트 구조화 계약

예제의 장면 의도는 다음 일곱 관점으로 구성한다. 값은 합성 데이터이며 자연어 문자열이다.

  1. 주제 — 장면의 중심 대상
  2. 행동 — 대상이 하는 일
  3. 장소 — 장면의 공간
  4. 카메라 — 시점·구도 설명
  5. 조명 — 빛의 방향·분위기 설명
  6. 스타일 — 표현 방식. 비어 있으면 선택된 카탈로그 기본값을 사용
  7. 제약 — 유지해야 할 조건

컴파일은 비어 있지 않은 값을 고정된 순서로 이어 붙인다. 주제·행동은 필수다. 빈 선택 항목은 생략하되, 필수 항목의 누락을 기본값으로 위장하지 않는다.

4. 모델 계열 프롬프트 어댑터 계약

이 데모는 백엔드 중립 어댑터 하나만 제공한다. 공통 일곱 관점을 읽어 하나의 문자열로 컴파일하고, 필수 입력을 확인한다. 해당 모델 계열 고유 포맷이나 실제 API payload를 만들지 않는다. 지원하지 않는 계열을 추가할 때는 새 어댑터와 그 출력 계약 검사를 함께 추가해야 하며, 미지원 선택을 묵시적으로 건너뛰지 않는다.

계약 요소예제 동작
입력정규화된 장면 의도와 선택된 카탈로그 항목
필수 입력주제, 행동
출력일곱 관점을 순서대로 담은 프롬프트 문자열
검증프롬프트가 비어 있지 않고 필수 문구를 보존하는지 확인
지원되지 않을 때명시적 ValueError; 기본 어댑터로 조용히 대체하지 않음

5. 실행 요청과 런타임 인터페이스

표준 진입점은 저장소 루트에서 실행하는 명령이다.

make example NAME=image-pipeline
python3 -m image_pipeline_demo

모듈은 fixture의 요청과 카탈로그를 읽고 결과 객체를 표준 출력에 표시한다. fake runtime은 외부 호출 없이 요청 식별자, 프롬프트 지문, 합성 상태를 반환한다. 입력 파일을 수정하지 않는다.

  1. 요청과 카탈로그 읽기
  2. 카탈로그 이름 확인
  3. 장면 필수 항목 검사
  4. 프롬프트 컴파일
  5. fake runtime 결과 작성
  6. 결과 메타데이터 확인

잘못된 JSON, 필수 필드 누락, 미등록 카탈로그는 성공으로 간주하지 않고 비정상 종료한다. 네트워크 오류나 GPU 상태는 이 예제 경로에 해당하지 않는다.

6. 결과 확인과 전달의 분리

예제 검증기는 결과의 합성 상태, 요청 식별자, 프롬프트 지문, 파일 형식 표식을 검사한다. 이 검사는 생성 이미지의 시각적 품질을 평가하지 않는다. 게시·전달은 구현되지 않았으며, 결과 객체가 반환됐다는 사실은 게시 완료를 뜻하지 않는다.

  • 실행 결과: fake runtime 응답 객체가 생성됐는가
  • 실제 파일: 이 예제는 이미지 파일을 생성하지 않으므로 해당 없음
  • 품질 검증: 입력과 출력 메타데이터의 계약만 확인
  • 게시 상태: 기능 범위 밖이며 실행하지 않음

7. 카탈로그 후보 수명주기

실제 운영에서 새 구성을 활성 카탈로그에 바로 덮어쓰지 않는다. 후보를 분리하고 출처·구성·검증 결과를 기록한 뒤 시험과 승인을 거친다. 활성화 후에는 새 항목이 선택 가능한지 확인하고 이전 정본을 복구할 수 있게 보존한다. 이 예제는 이 수명주기를 시뮬레이션하지 않고, 고정된 합성 카탈로그를 읽기만 한다.

  1. 후보 생성과 출처 기록
  2. 자산·기본값·템플릿·런타임 적합성 검토
  3. 시험과 결과 확인
  4. 명시적 승인
  5. 활성화 후 선택 가능성 확인
  6. 이전 정본 보존과 복구 확인

8. 트러블슈팅

  • 카탈로그 항목을 찾지 못함: fixture의 이름과 요청의 카탈로그 이름이 같은지 확인한다.
  • 주제·행동 누락: request fixture의 필수 필드를 채운다.
  • 프롬프트가 비어 있음: 의도 필드의 공백 문자열을 점검한다.
  • 테스트 탐색 실패: 저장소 루트에서 make test를 실행한다.
  • 실제 모델 실행을 기대함: 이 데모는 fake runtime만 제공한다. GPU·API 지원은 별도 구현이 필요하다.
