요청과 결과를 잇는 약속

매니저 에이전트가 일을 맡기고 작업 에이전트가 결과를 돌려줄 때, 대화만으로는 어떤 조건의 시도였는지와 실제로 무엇이 남았는지를 나중에 정확히 맞추기 어렵습니다. 요청과 응답을 파일로 남기면 한 번의 시도와 그 결과를 식별자·상태·산출물로 다시 대조할 수 있습니다. 파일은 대화를 대신하는 목적이 아니라, 수행 경계와 완료 근거를 서로 확인할 수 있게 하는 전달 기록입니다.

요청에서 응답까지

  1. 요청에는 목표, 완료 기준, 참조 경로, 금지 범위를 적습니다.
  2. 작업 에이전트는 요청과 참조를 읽고 정해진 범위에서 수행합니다.
  3. 응답은 원 요청과 같은 request_id와 실제 status를 돌려줍니다.
  4. 매니저 에이전트는 산출 경로를 열어 보고, 보고와 실제 결과를 대조합니다.

조건이 달라진 재시도는 새 식별자를 사용해야 응답이 서로 섞이지 않습니다. 완료됐다는 문장만으로 완료를 판단하지 않고, 응답 상태와 지정 경로의 파일을 함께 확인합니다.

응답 상태를 구분하는 이유

상태읽는 법확인할 것
done완료 기준을 충족했다고 보고된 상태필수 산출과 완료 근거가 실제로 있는지
partial일부 결과는 남았지만 완료 기준은 미충족남은 결과를 보존하고 빠진 조건을 기록했는지
failed수행에 실패한 상태실패 사유와 보존된 산출이 상태와 맞는지
blocked필수 입력·권한 또는 경계 문제로 진행할 수 없음막힌 조건을 구체적으로 밝혔는지

시간이 부족했다는 이유만으로 승인이나 입력이 없는 상태를 성공으로 바꾸지 않습니다. 상태는 결과를 요약하지만, 실제 권한과 파일 접근을 대신 통제하지는 않습니다.

무엇을 직접 확인할까

  • 요청과 응답의 식별자가 같은지 확인합니다.
  • 요청에서 약속한 완료 기준과 응답 상태가 서로 맞는지 살펴봅니다.
  • 응답에 적힌 산출 경로에서 파일을 직접 열어 확인합니다.
  • 게시나 외부 반영을 요청했다면 로컬 결과와 구분해 원격 대상도 따로 확인합니다.

시스템 단계별 상세 조건은 작업 흐름 참조, 용어는 용어 참조에서 찾아볼 수 있습니다. 재현 가능한 공개 참조 구현과 테스트는 저장소의 reference/ 및 tests/에 있습니다. 이는 설명을 보조하는 예시이며 실제 운영 시스템 전체를 설치하거나 재현하지 않습니다.
