이미지는 전체 작업 흐름 안에서 만들어집니다

요청은 지휘·작업 흐름과 필요한 지식 참조를 거쳐 이미지 산출로 이어집니다. 카탈로그 구성과 프롬프트를 실행하고 결과를 확인합니다.

의도 → 구성 → 프롬프트 → 실행 → 결과 확인의 흐름을 따라갑니다.

요청 목적에 맞는 검증된 구성을 고릅니다

같은 장면 의도라도 실행 구성이 달라지면 결과가 흔들릴 수 있습니다. 카탈로그는 목적에 맞는 검증된 구성 묶음을 선택하게 해 반복 가능한 출발점을 제공합니다.

카탈로그 선택은 결과를 보장하는 표시가 아니라, 실행에 사용할 구성을 결정하는 단계입니다.

전체 동작 흐름 · 입력 계층03 / 08

카탈로그는 서로 다른 입력을 최종 구성으로 연결합니다

자산, 기본값, 프롬프트 틀, 장면 설정, 실행 환경은 각기 다른 역할을 합니다. 한 목록에 섞어 다루지 않고 권위 있는 설정과 보조 참조를 구분해 실행 구성으로 모읍니다.

기본값이 실제 실행값이라고 단정하지 않습니다. 실행 시점의 선택과 환경까지 확인해야 합니다.

어댑터는 공통 의도를 계열별 실행 형식으로 바꿉니다

모델 계열마다 필요한 표현이나 입력 순서는 다를 수 있습니다. 어댑터는 장면의 핵심 의도를 유지하면서 형식을 조정하고 결과 구조를 검사합니다. 지원 어댑터가 없다면 미지원임을 명시해야 합니다.

조용히 입력을 버리거나 서로 다른 계열의 표현을 같은 것으로 가정하지 않습니다.

공식 실행 통로가 구성과 런타임을 확인합니다

준비된 구성을 공식 진입점에 전달하면 입력과 런타임 상태를 확인한 뒤 내부 실행 계층으로 이어집니다. 직접 우회 호출을 막아 선택한 구성과 실제 실행 경로가 어긋나는 위험을 줄입니다.

성공 보고와 실제 결과 확인은 서로 다른 단계입니다

실행 보고, 실제 파일의 존재와 내용, 품질 확인, 전달·게시 상태를 각각 확인합니다. 새 카탈로그도 후보로 분리해 출처와 시험을 기록하고 승인 후 활성화하며 기존 정본은 보존합니다.

1 · 후보출처 기록
2 · 검증시험·승인
3 · 활성선택·롤백 확인

확인된 결과는 보고로 돌아가고, 구성은 다음 요청에 재사용됩니다

검증된 이미지 산출은 결과 보고로 돌아갑니다. 카탈로그와 프롬프트 구성은 출처와 검증 상태를 유지하며 다음 요청에서 다시 선택할 수 있습니다. 이 순환이 산출 파이프라인을 전체 작업 흐름에 연결합니다.
