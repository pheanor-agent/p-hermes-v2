규칙과 기준은 일을 시작할 때도 판단할 때도 쓰입니다

에이전트는 세션을 시작하자마자 규칙과 사용자 선호를 읽고, 대화하며 판단할 때마다 스킬과 현재 파일을 씁니다.

작업 전후의 교훈은 그중 한 갈래이고, JOB 결과는 매일 요약으로 다시 모입니다.

에이전트에게 지식이란 무엇일까요?

저장한 기준도 지금 읽어야 사용할 수 있습니다

언어 모델은 이 시스템의 지난 실패나 오늘 바뀐 규칙을 스스로 알지 못합니다. 필요한 기록을 찾아 맥락 창에 넣어 줘야 씁니다.

그래서 기록을 남기는 것만큼 필요할 때 찾아 넣는 길이 중요합니다.

찾아 넣는 검색은 믿을 만할까요?

검색어가 달라지면 필요한 기록을 놓칠 수 있습니다

단어 중심 검색은 같은 단어가 들어간 기록은 잘 찾지만, 뜻은 같고 표현이 다른 기록(예: 시간 초과)은 놓칠 수 있습니다.

그래서 검색 결과는 언제나 후보로 다루고, 판단 전에 원문과 현재 파일을 직접 확인합니다.

기록은 무엇을 어디에 남길까요?

절차·교훈·현재 사실·선호·운영 원칙을 구별합니다

다시 쓸 수 있는 절차 안내는 스킬, 무슨 일이 왜 일어났는지는 교훈, 지금 확인할 사실은 원본 자료에 둡니다. 사용자 선호와 공통 운영 원칙도 각자 제자리에 기록합니다.

같은 절차를 여러 곳에 복사하지 않습니다. 사본은 반드시 어긋납니다.

작업 단위에서는 지식이 어떻게 돌까요?

작업 전 참고한 교훈을 작업 후 다시 점검합니다

작업이라는 단위에서 보면 지식은 원을 그립니다. 작업 전에는 관련 교훈과 결정을 모아 읽고, 작업 후에는 다시 쓸 만한 것만 남기며, 다음 날 요약으로 모입니다.

이 원은 지식이 쓰이는 여러 자리 중 하나입니다. 규칙·기억·스킬은 작업이 아니어도 늘 읽힙니다.

작업 전에는 구체적으로 무엇을 읽을까요?

이전 기록의 출처와 날짜를 함께 읽습니다

요청을 등록하면 요청서의 핵심어로 관련 교훈과 이전 JOB의 결정을 찾아, 출처·날짜와 함께 묶어 줍니다.

운영 원칙이나 이전 실패와 맞닿은 작업이면 교훈을 직접 더 검색해 원문으로 확인합니다.

찾은 후보는 그대로 근거가 될까요?

후보를 읽고 오늘의 실제 기준과 맞춥니다

검색 결과는 후보입니다. 단어 중심 검색은 의미상 맞는 자료를 놓칠 수 있고, 빈 결과가 자료 없음의 증명도 아닙니다.

후보 → 원문 → 현재 실물, 세 번째 단계에서야 판단 근거가 됩니다.

작업이 끝나면 무엇을 남길까요?

다시 참고할 원인과 해결만 교훈 후보로 남깁니다

실패 원인과 해결, 사용자 교정, 새로 확인한 사실처럼 다시 참고할 만한 교훈이 생기면 후보로 기록합니다.

후보는 언제 절차가 될까요?

같은 실패가 반복됐습니다. 무엇을 고칠까요?

수정된 절차가 다음 작업에서 어떻게 달라졌는지 확인해 봅시다.

반복된 원인을 기존 절차에 반영합니다

스킬은 다시 쓸 수 있는 절차 안내입니다. 같은 교훈이 되풀이되면 기존 스킬을 고쳐 다음에는 재발하지 않도록 합니다.

기록은 매일 어떻게 정리될까요?

요약에서 원본으로 돌아가 현재 사실을 확인합니다

작업 결과는 매일 요약으로 모입니다. 이 요약은 원본 자료를 대신하지 않으므로, 현재 사실은 언제나 원본에서 확인합니다.

이 모든 조각이 요청 하나에서 어떻게 함께 움직일까요?
