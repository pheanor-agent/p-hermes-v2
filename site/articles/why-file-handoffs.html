왜 파일 handoff가 필요한가

전체 흐름에서의 위치

p-hermes는 요청을 정의하는 지휘 에이전트(매니저)와 범위가 정해진 일을 맡는 작업 에이전트(워커)를 연결합니다. 파일 handoff는 전체 흐름 중 요청 전달과 결과 회신을 맡습니다. 목적은 파일 자체가 아니라 한 번의 시도와 결과를 서로 확인 가능하게 잇는 것입니다.

대화만으로는 무엇이 빠질까

긴 대화는 의도와 작업 수행이 한 맥락에 섞여 있습니다. 세션이 끊기거나 재시도되면 어느 목표를 어떤 조건으로 시도했는지, 이번 시도에서 실제로 남긴 파일이 무엇인지 확인하기 어렵습니다. 특히 “다시 해보기”가 같은 시도의 중복인지, 조건이 바뀐 새 시도인지 구분되어야 합니다.

요청 파일은 입력과 수락 조건을 고정하고, 응답은 같은 요청 식별자와 terminal 상태를 되돌려 줍니다. 따라서 결과를 말로만 신뢰하지 않고 ID를 맞춘 뒤 파일과 산출물을 직접 확인할 수 있습니다. 목표 식별자는 여러 시도에 걸쳐 유지할 수 있지만, 의도나 조건이 달라진 시도에는 새 요청 식별자를 부여합니다.

상태를 나누는 이유

완료(done)와 부분 성공(partial)은 같지 않습니다. 일부 산출물이 보존된 채 후속 단계가 실패했다면 부분 성공으로 기록해 산출물을 잃지 않게 합니다. 작업 흐름의 실행 단계 전에 입력이 경계를 벗어나면 차단(blocked), 보존된 산출물 없이 실패하면 실패(failed)입니다. 상태 이름만 적는 것으로 권한 통제가 완성되는 것은 아니므로 실제 입력 경로와 수행 권한도 별도로 제한해야 합니다.

이 저장소의 portable-worker는 합성 입력과 테스트 임시 폴더에서 이 계약을 보여줍니다. 상세 필드는 계약 참조, 환경별 수행은 환경 위키를 보세요.
