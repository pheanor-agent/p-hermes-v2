지휘 에이전트와 작업 에이전트의 흐름을 이해하고 확인하기 위한 문서입니다.

용어 참조

전체 흐름 속 위치

지휘 에이전트(오케스트레이터)가 요청을 정하고 작업 에이전트(워커)가 수행한 뒤, 작업 흐름의 검증 단계에서 결과를 확인합니다.

이 표는 문서에서 역할 이름과 단계 이름을 일관되게 읽기 위한 대응표입니다.

확정 용어 함께 쓰는 표현·대응 의미와 사용 범위
지휘 에이전트 오케스트레이터; Hermes 문서의 “상위 에이전트” 목표·완료 조건·경계를 정하고, 작업을 배정하며 결과를 확인하는 역할
작업 에이전트 워커; worker_dispatch.py와 WORKER.md가 가리키는 처리 역할 전달된 요청을 확인하고 정해진 범위 안에서 과제를 수행한 뒤 결과를 회신하는 역할
JOB(작업 건) JOB 별도 관리 절차로 등록·추적하는 작업 단위. 단순 작업을 모두 JOB이라고 부르지 않음
작업 흐름 단계 단계 요청 접수, 조사, 설계, 검토, 승인, 실행, 검증, 결과 검토 등 흐름의 구간
실행 단계 workflow의 execution 단계 작업 흐름 안에서 승인된 변경을 실제로 적용하는 특정 단계. 일반적인 “작업 수행”의 동의어로 쓰지 않음
작업 수행 수행 역할이 과제를 하는 일반 행위. 단계명인 “실행”과 구분
terminal 상태 done, partial, failed, blocked 한 번의 요청 처리에서 회신하는 종결 상태
요청 식별자 request_id 한 번의 요청 시도를 가리키는 불변 식별자
목표 식별자 goal_id 여러 요청 시도에 걸쳐 이어질 수 있는 목적의 식별자

코드 식별자, 파일명, 경로, 명령과 API 필드는 원래 표기를 그대로 유지합니다. “지휘 에이전트 / 작업 에이전트”는 역할명이며, orchestrator·worker 같은 코드 이름을 바꾸지 않습니다.
