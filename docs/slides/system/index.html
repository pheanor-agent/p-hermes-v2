설명

이 강의는 p-hermes의 전체 목적과 각 부분의 연결을 설명한다. 개별 도구의 사용법보다 요청이 결과와 다음 작업으로 이어지는 과정을 먼저 다룬다.

구현을 읽기 전에 시스템이 무엇을 남기고 왜 다시 확인하는지 이해하는 데 집중한다. 본문에는 이동용 링크가 없으므로 S 키로 발표자 노트를 열어 근거 항목의 링크를 이용한다.

한 문장 · 시스템의 목적

AI가 답하고 끝나지 않도록.

p-hermes는 작업의 상태, 지식, 자원, 생성 결과와 검토 근거를 연결해 복잡한 일을 여러 단계에 걸쳐 이어가는 AI 작업 시스템입니다.

현재 진행판단의 근거결과의 확인

답변 이후에 할 일과 확인한 내용을 남겨, 다음 행동을 결정한다.

홈의 핵심 문장과 보조 설명을 동일하게 제시한다.S02 · 02

설명

화면의 제목과 보조 설명은 홈의 문구를 그대로 제시한다. 핵심은 연결한다는 동사에 두고 설명한다.

좋은 답변을 만드는 일과 그 답변을 바탕으로 복잡한 일을 끝까지 확인하는 일을 구분한다. 진행, 자료, 실행 결과가 따로 남지 않도록 같은 요청과 연결한다.

진행

  • 120초 동안 홈 문구를 읽고 연결의 대상을 설명한다.
  • 현재 진행과 판단 근거가 다음 행동에 어떻게 쓰이는지 짧게 묻는다.

청중에게

결과만 남기고 판단 근거를 남기지 않았을 때 생기는 어려움을 생각한다.

해설

설명

여기서는 한 번 답하고 끝나는 사용 방식과 여러 단계의 일을 관리하는 방식을 대비한다. 모든 채팅 제품이 기록이나 도구를 제공하지 않는다고 단정하지 않는다.

자료를 요약해 달라는 요청 뒤에 문서 작성과 검토가 이어진다면, 답변 내용 외에도 남은 일과 확인된 결과를 관리해야 한다. p-hermes의 전체 구조는 이 연속된 작업을 설명한다.

진행

  • 120초 동안 왼쪽의 사용 범위를 설명한 뒤 오른쪽을 공개한다.
  • 응답의 품질과 작업의 이어짐을 서로 다른 질문으로 구분한다.

청중에게

해설

대화 길이와 별개로 목표에 맞는 결과와 검토 기록을 확인해야 한다.

설명

다섯 단계는 홈에서 전체 과정을 이해하도록 제시한 설명 순서를 따른다. 앞의 결과와 근거를 다음 단계가 활용한다는 관계에 집중한다.

이어짐은 여섯 번째 실행 단계로 추가하지 않는다. 검수와 기록을 남겼기 때문에 중단한 일을 다시 확인하거나 다음 요청에서 재사용할 수 있다는 결론으로 설명한다. 수정이 필요하면 앞의 작업을 다시 확인한다.

진행

  • 120초 동안 다섯 단계를 순서대로 공개한다.
  • 마지막에 이어짐 문장을 읽고 재개와 재사용을 구분한다.

조사·문서화자료의 출처를 확인하고 소개 문서의 주장에 근거를 연결한다.
프로젝트 실행완료 조건을 정하고 실행 결과를 검토·승인한 뒤 전달한다.
콘텐츠 제작같은 핵심 메시지로 이미지와 짧은 영상을 준비하고 함께 검토한다.

세 장면은 독립 기능의 목록이 아니라, 하나의 소개 요청에서 결과와 근거를 주고받는 과정을 설명한다.

설명

프로젝트를 외부에 소개할 자료를 준비한다는 하나의 설명용 요청을 가정한다. 조사에서 정리한 주장은 문서와 시각 자료가 함께 사용할 근거가 된다.

실행 과정에서 완료 조건을 확인하고, 제작 결과가 같은 메시지를 전달하는지 검토한다. 실제로 생성하거나 전달한 결과를 보여 주는 장면으로 해석하지 않는다.

진행

  • 120초 동안 세 행을 같은 요청의 관점으로 설명한다.
  • 자료에서 문서로, 문서의 메시지에서 제작과 검토로 이어지는 관계를 짚는다.

청중에게

해설

다섯 능력 · 같은 요청의 협력

다섯 능력이 진행과 결과를 함께 연결한다

공개 이름시스템 안에서 이어주는 관계
진행을 이어가기요청의 목표를 현재 진행과 다음 행동에 연결한다.
근거를 기억하기찾은 자료와 판단 이유를 다음 검토에 남긴다.
필요한 자원을 고르기작업의 목적에 맞는 도구·모델·참고자료를 선택한다.
결과물을 만들기공통 목표와 자료를 이미지·영상 산출물에 반영한다.
결과를 연결하고 검수하기여러 결과의 맥락을 맞추고 검토 내용을 진행 기록에 연결한다.

생성은 이미지·영상을 한 그룹으로 다루며, 검수와 기록까지 연결해야 다음 작업의 판단에 사용할 수 있다.

공개 이름을 먼저 읽는다. 내부 이름은 S 키 발표자 노트에서 처음 병기한다.S06 · 06

설명

공개 이름 뒤에 내부 이름을 이 장에서 처음 병기한다. 진행을 이어가기(Tasks), 근거를 기억하기(Knowledge), 필요한 자원을 고르기(Catalog), 결과물을 만들기(Image / Video), 결과를 연결하고 검수하기(Integration)로 대응한다.

본문에는 공개 이름을 먼저 배치하고 내부 이름은 보조 설명인 발표자 노트에 둔다. 생성은 이미지와 영상을 묶은 하나의 능력이며 통합까지 포함해 다섯 능력으로 설명한다.

이 다섯 능력은 앞 장의 다섯 단계와 일대일 대응하지 않는다. 검토한 내용을 다시 진행과 근거에 남기듯, 필요한 능력이 한 요청 안에서 협력한다.

진행

  • 120초 동안 각 행의 공개 이름과 연결 관계를 설명한다.
  • 내부 이름은 보조로만 소개하고 다섯 능력과 다섯 단계의 차이를 확인한다.

해설

소개 대상의 내용이 바뀌었다면 모든 결과를 무조건 새로 만들기보다 어떤 설명에 영향을 주는지 확인한다. 앞선 검토의 근거가 남아 있어야 유지할 부분과 다시 확인할 부분을 판단할 수 있다는 관계를 설명한다.

진행

  • 120초 동안 앞선 전달과 후속 요청을 대비한다.
  • 수정할 문장보다 먼저 확인할 자료와 판단을 묻는다.

설명

기존 전체 구조 강의 O04의 자료 선택 문제를 날짜 비교의 세부 예제 없이 요약한다. 자료가 눈에 띄었다는 사실과 현재 요청에 맞는다는 판단을 구분한다.

소개할 제품이나 독자가 다른 자료를 무심코 재사용하면 문서와 제작 결과가 함께 잘못될 수 있다. 자료가 설명하는 대상과 조건을 살피고 사용 이유를 남기는 것이 전체 작업의 근거를 유지하는 방법이라고 설명한다.

진행

  • 120초 동안 후보 확보와 근거 채택의 차이를 설명한다.
  • 자료의 최신성 외에 확인할 항목을 하나씩 듣는다.

설명

기존 전체 구조 강의 O09의 참조 변경 문제에서 구현 세부를 제외하고, 변경이 다른 결과에도 영향을 줄 수 있다는 개념만 재구성한다.

이미지를 바꾸면 이를 사용하는 영상과 소개 문구를 함께 살펴야 한다. 파일을 교체한 사실만으로 이전 검토가 새 결과에도 적용된다고 판단하지 않는다. 다시 확인한 내용을 기록에 남겨 다음 요청에서 무엇을 사용할지 알 수 있게 한다.

진행

  • 120초 동안 교체부터 기록까지의 관계를 설명한다.
  • 실제 변경 감지나 재검수가 자동으로 실행되었다고 주장하지 않는다.
