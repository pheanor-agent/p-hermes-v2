설명

이 세 책임은 여러 종류의 작업을 지원합니다. 다음 단계에서 이미지와 영상을 공개합니다. 이미지는 공간과 입력, 영상은 샷과 시간을 관리합니다. 모든 작업이 다섯 분야를 차례대로 통과하는 것은 아닙니다.

실행 근거: content/slides/evidence.json · 요청 7, 첫 반영 뒤 현재 8T04 · 03

설명

리비전은 변경 전후를 구분하는 상태의 번호입니다. 화면의 두 요청은 모두 번호 7을 읽었습니다. 번호가 같다는 것은 같은 시점의 상태를 기준으로 판단했다는 뜻입니다.

A가 먼저 반영됩니다. 현재 번호는 8로 바뀌지만 B가 읽은 번호는 여전히 7입니다. 여기서 바로 답을 보여주지 말고 B의 수정이 반영될지 생각할 시간을 줍니다.

B가 제출한 번호와 현재 번호가 다르므로 오래된 수정은 거부됩니다. 공개 Store는 상태를 바꾸기 전에 이 값을 비교합니다. 두 요청을 모두 받아들이면 먼저 반영한 변경을 놓칠 수 있습니다.

이 번호와 결과는 합성 작업을 실제 Store에서 실행해 얻었습니다. 번호를 맞추는 것 외에도 현재 상태에서 허용된 행동인지, 승인 대상 계획이 일치하는지 확인해야 합니다.

진행

  • 첫 진행: A 반영, 현재 번호 8 공개.
  • 두 번째 진행: 질문을 보여주고 15초 기다립니다.
  • 세 번째 진행: B 거부 공개. 두 번호를 번갈아 가리킵니다.

설명

내용을 펼치면 runtime 필드가 다릅니다. 버전 표시는 유지됐지만 메타데이터의 내용이 바뀐 상황입니다. 앞에서 선택한 내용과 같은지 확인하려면 내용에 대한 비교가 필요합니다.

해시는 내용을 계산한 값입니다. 같은 규칙으로 계산한 해시가 달라졌다면 내용이 달라졌음을 발견할 수 있습니다. 화면은 읽기 쉽도록 해시의 앞부분만 보여주며 전체 값은 실행 근거 파일에 있습니다.

이 검사는 내용 변경을 확인합니다. 자산의 미감이나 실제 런타임 실행 성공을 점수화하는 검사가 아닙니다.

진행

  • 두 버전 이름을 먼저 비교합니다.
  • 다음 단계에서 runtime 차이를 공개합니다.
