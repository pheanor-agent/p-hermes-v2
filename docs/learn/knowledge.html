수집한 정보, 검토한 지식, 검색된 결과 사이의 연결을 보존합니다.

자료를 모은 뒤, 사용할 근거를 고릅니다

원문, 등록된 지식, 검색 결과는 서로 다른 역할을 합니다.

대화에서 본 문장이나 파일의 내용은 우선 수집한 자료입니다. 그중 어떤 내용이 어떤 조건에서 유효한지 검토하고 출처를 붙이면 재사용 가능한 지식이 됩니다. 검색 결과는 그 지식 중 현재 질문과 관련된 항목을 찾아 보여주는 표현입니다.

운영 구조에서는 수집·등록·인덱스와 같은 여러 경로를 구분해 읽어야 합니다. 작업 완료가 곧 모든 자료의 지식 승격을 뜻하지 않습니다. 공개 참조 구현은 출처와 공개 적합성을 확인한 레코드를 등록하고, 활성 항목을 검색하는 좁고 명확한 계약을 제공합니다.

램프의 제품 색을 알아야 한다면 과거 대화에 나온 색 이름만 가져오지 않습니다. 어느 제품 버전의 자료인지, 어떤 출처에서 확인했는지 함께 남겨야 다음 이미지 제작에서 같은 근거를 사용할 수 있습니다.

  • 검색 결과에 원문 링크가 필요한 이유를 설명해 보세요.

출처가 있어도 두 자료가 서로 다른 내용을 말할 수 있습니다.

덧붙이는 설명

중요한 것은 저장한 양뿐 아니라 어떤 자료를 판단의 근거로 채택했는지 남기는 일입니다.

두 색 정보가 충돌하면 적용 범위를 봅니다

최신이라는 이유만으로 모든 기존 지식을 덮어쓰지 않습니다.

예시 자료 A는 LUMA의 초기 시안을 파란색이라고 설명하고, 자료 B는 이번 소개용 버전을 짙은 초록색이라고 설명합니다. 두 문장은 서로 모순처럼 보여도 대상 버전이 다르면 각각 유효할 수 있습니다. 먼저 제품과 버전, 관측 시점을 확인합니다.

등록할 때 출처와 적용 범위를 함께 기록하면 현재 작업에 맞는 근거를 골라낼 수 있습니다. 결론을 바꾼 경우에는 이전 근거를 잃어버리기보다 무엇이 달라졌는지 추적할 수 있게 남깁니다.

자동 검색은 관련 항목을 제시하는 역할입니다. 검색 점수가 높다는 이유만으로 사실이 확정되는 것은 아닙니다. 공개 실습의 부분 문자열 검색에서도 실제 채택 판단은 항목의 출처와 상태를 확인한 뒤 해야 합니다.

  • 자료 A를 즉시 삭제하지 않고 남겨둘 수 있는 이유는 무엇인가요?
지식 · 출처를 가진 판단 위키공개 구현 소스

채택한 근거를 프로그램이 재사용하려면 등록과 검색의 연결을 유지해야 합니다.

덧붙이는 설명

A와 B는 충돌을 설명하기 위해 만든 합성 자료입니다. 표시한 제품 색은 실제 제품을 조회한 결과가 아닙니다.

등록된 항목을 다시 찾을 수 있게 만들기

고유 식별자와 활성 상태가 검색의 기준이 됩니다.

python
from p_hermes.store import Store

with Store("demo-output/workspace.sqlite3") as store:
    hits = store.search("lamp")
    print([item["id"] for item in hits])
    # ['composition-note']

지식 항목은 본문만 있는 메모보다 식별자, 출처, 상태를 함께 가진 레코드로 다루는 편이 좋습니다. 같은 식별자의 중복 등록은 충돌로 처리하고, 이름을 파일 경로로 사용해 의도하지 않은 위치에 쓰는 일도 피해야 합니다. 공개 적합성은 public 선언과 출처·라이선스 필드로 받으며, 프로그램이 본문 속 개인정보나 권리 관계를 자동 판정하지는 않습니다.

참조 구현은 데이터베이스의 고유 키로 중복을 막고, 활성 항목의 제목과 본문에서 대소문자를 구분하지 않는 부분 문자열 검색을 수행합니다. 의미가 비슷해도 해당 문자열이 없으면 찾지 못하고, 결과는 식별자 순서로 반환합니다. 검색 구현과 그 한계를 함께 이해해야 합니다.

어떤 항목을 근거로 선택했다면 결과에 그 식별자를 남깁니다. 검색어는 다음번에 결과 순서가 달라질 수 있지만, 채택한 항목의 식별자는 무엇을 읽었는지 확인하는 연결점이 됩니다.

  • 검색어만 남기는 것과 채택한 지식 ID를 남기는 것의 차이는 무엇인가요?

이 연결은 정보가 오래되거나 사용을 중단해야 할 때 특히 중요해집니다.

덧붙이는 설명

이 예제의 검색은 부분 문자열 검색입니다. 벡터 검색이나 자동 요약은 포함하지 않습니다.

오래된 근거는 재사용 경로에서 제외합니다

지식의 수명도 관리해야 검색 결과를 신뢰할 수 있습니다.

제품 조건이 바뀌어 이전 설명을 더 이상 사용하면 안 되는 경우가 생깁니다. 이때 기존 결과의 출처 연결을 유지하면서 새 검색에는 나오지 않도록 항목을 퇴역시키는 방법을 사용할 수 있습니다.

참조 구현에서는 퇴역된 지식이 활성 검색 결과에 포함되지 않는지 검사합니다. 항목 등록이 성공했다는 테스트와 퇴역 후 검색에서 빠지는 테스트는 서로 다른 동작을 확인합니다. 자료 갱신과 검색 반영을 함께 검증해야 합니다.

실제 검색 인덱스를 별도로 운영한다면 저장 원본과 인덱스의 갱신 상태가 어긋날 수도 있습니다. 어떤 저장소가 기준인지, 언제 다시 색인하는지 문서에 명확하게 남겨야 합니다. 공개 구현의 직접 조회를 별도 인덱스 운영의 실증으로 확대하지 않습니다.
