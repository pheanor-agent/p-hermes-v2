통합 · 한 결과를 끝까지 설명하기

실습을 실행하고, 실패를 추적하고, 자기 작업의 계약을 설계합니다.

이 주제의 강의 보기
한 결과에서 판단의 근거까지 돌아가기실행하고, 바꾸고, 다시 확인하기자기 작업의 계약을 설계해 보세요

한 결과에서 판단의 근거까지 돌아가기

연결 기록은 왜 이 결과가 나왔는지 설명하게 합니다.

LUMA 결과에서 시작해 뒤로 돌아가 봅시다. 영상의 샷은 이미지 파일을 참조하고, 이미지는 계획과 선택한 자원에 연결됩니다. 계획의 제품 조건은 채택한 지식에, 전체 전달 기준은 작업 목표에 연결됩니다.

이 연결을 lineage라고 부릅니다. 각 파일을 큰 문서 하나에 복사하는 대신 식별자와 내용 digest로 연결하면, 어떤 부분이 바뀌었는지와 영향을 받는 결과를 찾기 쉽습니다.

공개 데모는 새 결과 폴더에 workspace.sqlite3, image-plan.json, storyboard.svg, artifact.json, timeline.json, report.json을 만듭니다. SVG는 고정된 예시 구도를 직접 작성한 결과이며 prompt를 해석해 렌더링하는 생성기는 아닙니다. report.json의 계획, 자원 digest, 근거 참조와 파일 기록을 대조하는 것이 실습의 핵심입니다.

  • 영상의 제품 색이 잘못됐다면 어떤 연결을 따라가겠습니까?

이 연결을 직접 만들고 일부 입력을 바꾸어 실패를 관찰해 봅니다.

덧붙이는 설명

식별자의 존재와 의미상 연결은 각각 확인해야 합니다. 실제 파일과 연결 기록을 대조합니다.

실행하고, 바꾸고, 다시 확인하기

정상 실행과 의도한 실패를 함께 관찰하면 계약이 보입니다.

shell
python -m pip install -e .
p-hermes demo --output demo-output
p-hermes verify-artifact demo-output/artifact.json --root demo-output

먼저 저장소의 설치 안내에 따라 공개 CLI를 준비하고 demo 명령에 아직 존재하지 않는 결과 폴더를 지정합니다. 생성된 storyboard.svg를 열어 구도를 살핀 뒤 report.json의 작업, 근거, 파일 연결을 확인합니다. 같은 화면에서 코드가 보장하는 내용과 직접 관찰해야 할 내용을 구분합니다.

다음으로 이미지 컴파일 입력의 필수 필드를 지우거나, 참조한 이미지의 바이트를 바꾸어 보세요. 각각 컴파일 단계와 산출물 검사 단계에서 실패해야 합니다. 실패가 발생한 위치와 메시지를 기록하고 원래 입력으로 복구합니다.

영상 검사를 실습하려면 로컬 ffmpeg와 ffprobe가 필요합니다. 실제 영상 파일을 만든 뒤 inspect-video에 기대 길이를 전달하고 측정 결과를 확인합니다. 의존성이 없어서 실행하지 못한 검사는 실행한 것으로 기록하지 않습니다.

  • 각 실패가 전체 시스템의 어떤 계약을 검사했는지 한 문장으로 적어 보세요.

자기 작업의 계약을 설계해 보세요

목표, 근거, 선택, 산출물, 검수가 이어지면 다음 행동이 명확해집니다.

자신이 자주 하는 작업 하나를 고르세요. 조사 보고서라면 근거 선택과 문서 산출물이 중심이고, 제품 영상이라면 이미지와 샷 계획까지 필요합니다. 이름이 같은 다섯 단계를 억지로 만드는 대신 필요한 책임을 찾습니다.

먼저 전달할 결과와 완료 기준을 적습니다. 이어서 어떤 출처를 채택하고 어떤 자원을 고정하며 어떤 파일을 남길지 정합니다. 마지막에는 자동으로 확인할 항목과 사람이 직접 읽거나 볼 항목을 나눕니다.

이제 실패 하나를 가정해 보세요. 근거가 바뀌거나 파일이 교체되거나 실행 결과가 불명확할 때 어디로 돌아가야 하는지 설명할 수 있다면, 시스템의 구성요소를 자기 작업의 판단과 연결한 것입니다. 분야별 위키와 공개 코드를 따라 필요한 부분을 더 깊게 살펴볼 수 있습니다.

  • 네 질문의 답이 연결되는지 확인하고, 빠진 입력 한 가지를 보완해 보세요.
