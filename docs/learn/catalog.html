04 / 01 · 카탈로그 · 실행할 자원을 고르기

이름 뒤에 있는 자원 관계를 읽기

자원을 고를 때는 버전, 실행 환경, 지원 조건을 함께 봅니다.

모델이나 워크플로우의 이름만으로 실행 가능성을 판단할 수는 없습니다. 같은 이름의 다른 버전이 서로 다른 입력을 받을 수 있고, 실행 환경이 달라 지원하는 노드나 기능이 다를 수 있습니다. 카탈로그는 이런 관계와 조건을 명시적으로 설명합니다.

운영 설계의 family, variant, release, runtime 같은 구분은 자원을 여러 층으로 이해하게 돕습니다. 공개 참조 구현은 그중 정확한 식별자와 버전, 실행 환경, 내용 digest를 고정하는 선택 계약을 실습합니다.

램프의 이미지를 만들 자원을 고른다면 단순히 유명한 모델을 찾기보다 필요한 규격과 입력을 지원하는 구성인지 먼저 확인합니다. 선택 근거가 남아야 같은 결과를 다시 만들 때 환경 변화의 영향을 설명할 수 있습니다.

  • 같은 이름과 버전인데 파일 내용이 바뀌면 무엇으로 감지할 수 있나요?

04 / 02 · 카탈로그 · 실행할 자원을 고르기

호환되는 후보를 명확하게 선택하기

모호한 선택은 실행 전에 해결합니다.

후보 A는 필요한 입력을 지원하지만 후보 B는 다른 실행 환경을 요구한다고 가정합시다. B가 더 최근에 등록됐다고 해서 현재 작업에 적합한 것은 아닙니다. 현재 계획의 조건과 후보의 계약을 비교해야 합니다.

선택기는 원하는 식별자, 버전, 실행 환경에 맞는 항목을 확인하고 내용 digest까지 고정합니다. 조건에 맞는 후보가 모호하거나 지원되지 않는다면 임의로 첫 항목을 고르지 않고 오류를 반환하는 편이 재현에 유리합니다.

카탈로그의 사용 가능 상태는 실제 생성 결과의 품질을 보장하지 않습니다. 등록 정보의 정합성, 실행 환경의 준비 상태, 결과의 시각 품질은 각기 다른 확인 대상입니다.

  • 카탈로그에서 사용 가능하다고 표시된 항목에도 실행 후 검수가 필요한 이유는 무엇인가요?

선택한 자원은 이미지 계획의 값을 실행 입력으로 연결할 때 사용됩니다.

발표자 설명

A/B 우열 순위를 장식 점수로 표현하지 않고 조건의 충족 여부로 비교합니다.

04 / 03 · 카탈로그 · 실행할 자원을 고르기

의미 있는 값과 노드 입력을 연결하기

바인딩은 계획의 필드가 실행 그래프의 어디로 가는지 정합니다.

json
{
  "bindings": {
    "prompt": ["text", "prompt"],
    "width": ["canvas", "width"],
    "height": ["canvas", "height"],
    "seed": ["noise", "seed"]
  }
}

사람이 이해하는 계획에는 prompt, width, height, seed 같은 필드가 있습니다. 반면 실행 그래프는 특정 노드의 특정 입력에 값을 요구합니다. 바인딩은 두 표현 사이의 명시적인 대응표입니다.

참조 구현의 이미지 컴파일러는 먼저 template_digest로 원본 그래프 전체가 선택한 버전과 같은지 확인합니다. 이어서 네 필수 필드를 정해진 node/input 위치에 넣고, 변환 전후를 검증합니다. 노드 이름을 추측하지 않으며 원래 템플릿도 그대로 보존합니다.

이 구조는 계획 내용과 실행 환경의 결합 지점을 드러냅니다. 실행 그래프가 바뀌면 바인딩을 함께 갱신해야 하고, 바인딩의 대상이 사라졌다면 실행 전에 오류를 확인할 수 있습니다.

  • 원본 워크플로우 템플릿을 수정하지 않고 복사본을 만드는 이유는 무엇인가요?

이제 선택한 자원이 시간이 지나도 같은 자원인지 확인하는 방법을 봅니다.

발표자 설명

코드에서 실제 필수 필드 네 개와 바인딩 위치를 짚어 기술 단계로 연결합니다.

선택한 내용이 바뀌면 다시 검토합니다

고정한 식별 정보와 실제 내용을 함께 확인합니다.

카탈로그 항목의 이름과 버전 표시가 같아도 바인딩이나 조건은 바뀔 수 있습니다. 참조 구현의 digest는 항목 JSON 내용을 요약합니다. 선택 당시의 값과 지금 읽은 항목의 값이 다르면 이전에 검토한 항목과 동일하다고 말할 수 없습니다. 모델 파일 자체의 동일성은 별도 파일 digest가 있어야 확인할 수 있습니다.

참조 구현의 선택 검사는 digest의 불일치와 지원되지 않는 환경을 실패로 다룹니다. 또한 입력이 모호한 경우도 실패로 드러내어, 어떤 항목이 사용됐는지 결과 뒤에서 추측하지 않도록 합니다.

운영에서 자원을 폐기하거나 교체할 때는 새 선택 대상에서 제외하는 것과 이전 결과의 재현에 필요한 기록을 보존하는 것을 함께 고려합니다. 카탈로그는 선택 목록이면서 변경의 영향을 찾는 연결 자료입니다.
