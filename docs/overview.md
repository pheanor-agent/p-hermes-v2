# 전체 지도: 요청에서 검증된 결과까지

[시작](index.md) · [강의 목차](lectures/index.html) · [전체 지도 슬라이드](lectures/prototype.html#map)

## 다섯 시스템의 역할
작업은 범위와 책임을 정합니다. 지식은 출처가 있는 정보를 제공합니다. 카탈로그는 사용할 자산과 버전을 고릅니다. 이미지와 영상은 시각적 의도를 결과물로 바꿉니다.

이 관계는 이해를 돕는 **제안된 교육 모델**입니다. 다섯 시스템이 현재 하나의 자동 파이프라인으로 완전히 통합돼 있다는 주장은 아닙니다.

## 작업: 진행보다 중요한 승인 경계
[흐름 슬라이드](lectures/prototype.html#flow)
요청 → 설계 → 승인 → 실행 → 검증이라는 책임 흐름을 먼저 이해합니다. 실제 조사에서는 호환 진입점에서 상태 전이 gate로, 이어 CAS 변경 helper로 연결되는 정적 호출을 확인했습니다. 모든 쓰기가 CAS라는 주장은 하지 않습니다. 완료 후처리와 지식 등록도 동일한 기능이 아닙니다.

## 지식: 저장과 신뢰는 다릅니다
수집한 정보는 출처·분류·검토 상태를 가지고 등록되고, 탐색용 인덱스로 이어져야 합니다. 실제 등록 코드의 메타데이터 검증을 확인했지만 end-to-end 검색 성공은 실행하지 않았습니다. 일부 요약 경로는 placeholder 상태이므로 완성된 자동 요약으로 소개하지 않습니다.

## 카탈로그: 목록이 아니라 선택 계약
자산 식별자와 버전을 고정하고 허용된 파라미터를 연결합니다. 실제 코드에서 카탈로그 계약을 읽는 WorkflowCompiler를 확인했습니다. 프롬프트 컴파일러와는 별개입니다. 정적 검사와 실제 생성 성공은 다릅니다. 일부 overlay는 기록만 수행하므로 자동 환경 치환으로 과장하지 않습니다.

## 영상: 시간에 따라 의미를 연결하기
[타임라인 슬라이드](lectures/prototype.html#timeline)
장면의 시작 상태, 변화, 끝 상태를 먼저 설계하고, 참조·카메라·길이를 연결합니다. 실제 샷 입력 검증 구조는 관측했지만, validator가 허용하는 모드가 모두 실행 성공했다고 해석해서는 안 됩니다. 강의 타임라인은 교육용 개념도입니다.

## 이미지: 비교 기준을 먼저 정하기
[비교 슬라이드](lectures/prototype.html#compare)
피사체의 위치, 대비, 시선 방향을 기준으로 비교합니다. 시안의 SVG는 직접 작성한 교육용 도식이며 모델 출력이나 품질 벤치마크가 아닙니다.

## 작은 데이터 계약부터 검증하기
[계약 슬라이드](lectures/prototype.html#contract)
합성 입력에 template_id, variant_id, release_id가 있고 selected_count가 1인지 검사합니다. 이 작은 예제는 교육용 제안이며 운영 스키마를 대체하지 않습니다. 정적 테스트는 이 데이터 계약만 검증하며 GPU나 API를 호출하지 않습니다.

## 증거를 읽는 방법
- **관측**: 특정 소스를 읽어 확인한 구조. 실행 성공 아님.
- **제안**: 교육 모델·개선 방향·합성 예제.
- **실행 입증**: 해당 입력과 버전에 대해 실제 검사한 결과. 다른 환경의 성공 보장 아님.

현재 결과물은 대표 화면 검증용 프로토타입입니다. 전체 배포와 시스템 재현 가이드는 후속 단계입니다.
