# 작업 근거 확인 예제

## 목적
합성 요청과 합성 지식 자료만 사용해 후보 발견, 출처 확인, unknown 보존, 사람 검토 대기를 구분합니다. 검색 결과를 사실로 단정하거나 검토 전에 승격하면 테스트가 실패합니다.

## 전체 흐름 속 위치

```text
합성 요청 + 후보 fixture → 원문·출처 상태 확인 → 검토 대기 표시 → 사람의 다음 결정
```

한 줄 실행: 저장소 루트에서 `make example NAME=knowledge-context-check`.
전체 테스트: `make test`.

Python 표준 라이브러리만 사용합니다. GPU, 패키지 설치, 네트워크, 실제 사용자 파일은 사용하지 않습니다. 모든 입력은 합성 fixture입니다.

## 실행

```bash
make example NAME=knowledge-context-check
```

예제는 자료의 존재 여부와 출처·날짜·검증·검토 상태를 따로 보고합니다. `unknown`은 확인되지 않은 값을 추정하지 않고 보존한 상태입니다.

## 에이전트 사용

`README.md`, `PROMPT.md`를 읽고 `PROMPT.md`의 과제를 이미 사용하는 코딩 에이전트에 전달합니다. 에이전트는 합성 fixture 범위에서만 작업합니다.

## 한계

이 예제는 검색 엔진이나 자동 승격 시스템이 아닙니다. fixture 안 후보의 상태를 점검하는 작은 계약 예제입니다. 후보가 없다는 결과는 fixture 범위일 뿐, 지식 전체에 자료가 없다는 증거가 아닙니다.
