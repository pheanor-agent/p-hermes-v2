작업 흐름을 찾아 쓰기

강의 02의 개념 설명을 반복하지 않고, 현재 계약·단계·검사·적용 경계를 원본 파일에서 확인합니다.

1. 경로와 tier 식별

현재 light 경로는 light-v2이며 신규 light JOB에만 활성입니다. 이미 생성된 JOB과 full/simple 프로필에는 자동 적용되지 않습니다. simple은 JOB을 만들지 않는 즉답 경로입니다. tier 선언은 core/skills/custom/workflow/v2/tiers/light.yaml, 활성 프로필과 안내 경로는 core/skills/custom/workflow/v2/registry-v2.json에서 확인합니다.

2. 단계 계약

정본은 core/skills/custom/workflow/v2/contract.yaml입니다. light 단계는 아래 순서이며 계약은 목적, 입력, 필수·선택 제출물, 통과 조건, 검사, 다음 단계를 정합니다.

  1. request: 범위와 완료 조건 고정; 필수 request.md.
  2. execution: 허용 경계 안에서 수행; 필수 execution.md, 산출물은 요청에 따라.
  3. verification: 테스트와 실물 대조; 필수 verification.md.
  4. done: 근거와 결과 정합 확인; 필수 result.md.

실제 안내 파일: steps/light-request/SKILL.md, steps/execution/SKILL.md, steps/verification/SKILL.md, steps/complete/SKILL.md. 저장소 README와 계약 원문을 함께 읽어 버전 차이를 확인하세요.

3. 실행 및 검사 명령

신규 light JOB 생성은 다음 형태입니다. 기본 JOB 유형과 측정 가능한 목표를 명시합니다.

bash <Hermes 설치 경로>/core/scripts/create-job.sh -y --tier light 기능 "작업 제목" -g "측정 가능한 목표와 완료 조건"
bash <Hermes 설치 경로>/scripts/workflow-gate.sh JOB-XXXX advance

각 단계 전이는 gate가 수행하며, 누락된 계약·산출물·조건은 통과하지 않습니다. 현재 구현과 실행 인자는 workflow-gate.sh, core/skills/custom/workflow/v2/runner.py, check.sh에서 확인합니다. 이 페이지의 명령은 설명용이며 자동 실행되지 않습니다.

4. 승인·결정 원장 참조

light 계약 자체에는 별도 approval 단계가 없습니다. 단, 사용자가 명시한 별도 승인 경계가 있으면 tier를 낮춰 이를 생략할 수 없습니다. full 계약은 plan, 결정 원장, 승인 이벤트를 연결하며 최신 revision과 승인 대상 내용의 결속 여부를 확인합니다. 전체 계약의 승인 필드는 canonical contract.yaml과 구현 검사를 따라야 합니다.

5. timeout과 terminal 결과

필수 산출 완료 여부를 기준으로 terminal 상태를 사실대로 정합니다.

  • done: 필수 산출이 모두 끝났고 결과가 완료 조건을 만족.
  • partial: 일부 단계만 끝났지만 생성된 산출은 보존하고 남은 일을 기록.
  • failed: 실행 오류로 목표 산출을 완료하지 못함.
  • blocked: 안전 경계·필수 입력·권한 또는 재현 오류로 진행 불가.

timeout이나 실패 때문에 이미 만든 파일을 버리지 않습니다. 완료 여부는 실행 기록과 파일을 다시 읽어 확인하고, 권장 검증이 미완이면 필수 산출과 구분해 보고합니다.

6. 운영 상태와 호환성

현재 구현 문서(workflow/v2/README.md)는 light-v2가 신규 light JOB에만 활성이고, full-v2·simple-v2는 비활성 prototype이라고 명시합니다. 운영 상태는 README만으로 단정하지 말고 registry와 gate를 함께 확인합니다. 과거 JOB은 생성 당시 프로필에 고정되며 새 registry 변경만으로 재핀하지 않습니다.
