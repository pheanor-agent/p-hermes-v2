실행 가능한 작은 약속

무엇을 부탁했고, 무엇이 돌아왔는가

요청에 담을 것

{
  "request_id": "attempt-002",
  "goal_id": "goal-42",
  "intent_revision": 2,
  "inputs": ["brief.txt"],
  "acceptance": "terminal response exists",
  "policy": {"dry_run": true}
}

응답은 상태와 함께

{
  "request_id": "attempt-002",
  "status": "partial",
  "artifacts": ["draft.txt"],
  "error": "later step unavailable"
}

done

요청의 완료조건을 충족했다고 worker가 보고합니다. 소비자는 ID를 대조하고 산출물을 읽습니다.

partial · failed · blocked

부분 산출물은 보존하고 이름을 남깁니다. 막힌 이유와 남은 작업을 숨기지 않습니다.

이 예제는 로컬 파일 기반 교육용 계약입니다. 스케줄러·분산 잠금·실서비스 연결을 제공한다고 주장하지 않으며, done은 명시한 acceptance 조건을 worker가 충족했다고 보고할 때만 사용합니다.
