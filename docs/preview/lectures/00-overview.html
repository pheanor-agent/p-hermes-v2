강의 00 · 전체 그림

요청이 결과가 되기까지

사람의 의도를 지휘 에이전트와 작업 에이전트가 이어받아, 확인 가능한 결과로 돌려주는 구조입니다.

처음 등장: 지휘 에이전트(오케스트레이터) · 작업 에이전트(워커)

핵심 흐름 · 단계별로 보기

요청 카드는 경로를 따라 움직이고, 현재 단계가 밝혀집니다

모든 예시는 교육용 합성 데이터입니다.

배경 · 왜 나누는가

대화가 이어지는 것과 결과가 맞는 것은 다릅니다

이어갈 정보는 기록으로, 완료 판단은 결과 확인으로 분리합니다.

축 1 · 지휘와 작업

계획을 세우는 역할과 맡은 범위를 수행하는 역할

축 2 · 작업 흐름

계획·승인·실행·검증은 한 요청 안의 서로 다른 단계입니다

축 3 · 지식

필요한 근거를 찾아 현재 상태와 대조합니다

여기서는 역할만 표시합니다. 실제 지식 경로는 복구된 실물을 확인한 뒤 다룹니다.

축 4 · 이미지 생성

요청을 구성하고 결과를 검사하는 파이프라인

하나의 요청 · 네 축 통과

요청의 목표는 단계마다 더 구체적인 산출로 바뀝니다

합성 요청→지휘가 범위 정리→작업 흐름에서 승인→지식 참조·이미지 산출→결과 확인

예: 교육용 그림 한 장. 예시는 이 시스템의 작동만 보여주는 합성 상황입니다.
