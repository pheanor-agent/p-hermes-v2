1. 무엇을 어디에 남기나

지식 저장 위치는 orchestration/CLASSIFICATION.md 한 표가 정합니다. 같은 내용을 여러 곳에 복사하지 않습니다.

답하는 질문정본 위치읽는 방법
지금 어떻게 하나 (절차)주제 스킬 SKILL.md(8KB 이하) + references/상황에 맞는 스킬을 그때 불러옴
그때 무슨 일이 왜 있었나 (사건·교훈)knowledge/lessons/<id>_lessons.md + index.md 한 행, 근거는 JOB 폴더index.md를 핵심어 2~3개로 grep
지금 무엇이 있나 (현재 사실)실물 정본: STRUCTURE.md, registry, config, 스크립트실물을 직접 읽음
사용자 선호MEMORY.md(매니저 런타임 메모리 포함)세션 시작 때 자동 로드
규칙 (역할·권한·금지·의무)POLICY.md(지휘), WORKER.md(작업)진입 문서 AGENTS.md가 가리킴

순간읽거나 쓰는 것

3. context pack

작업 에이전트에 보내는 요청은 dispatcher가 context pack을 자동으로 만들고, 경로를 환경변수 CONTEXT_PACK으로 넘깁니다. 작업 에이전트는 이 파일을 먼저 읽습니다(WORKER.md 3절). 지휘 에이전트가 JOB을 직접 시작할 때는 직접 실행합니다.

python3 <로컬 운영 루트>/core/scripts/context_pack.py <JOB>/request.md --out <JOB>/artifacts/context-pack.md

결과 첫 줄에 상태가 적힙니다.

  • found: 관련 후보가 있음 · no_match: 검색은 정상이나 관련 후보 없음 · search_error: 검색이 실패해 후보를 판단할 수 없음
  • completeness=partial: 일부 자료를 읽지 못함. path_errors는 이름을 읽을 수 없어 건너뛴 파일 수입니다.
  • 각 후보에는 본문 확보 여부·검증 상태·날짜 같은 출처 상태가 붙습니다. 날짜를 알 수 없으면 unknown이며, 오래됐다는 표시는 최신성 확인이 필요하다는 뜻이지 틀렸다는 판정이 아닙니다.

4. 결과를 읽는 법

  • 검색은 단어 중심이라 같은 뜻의 다른 표현을 놓칠 수 있습니다. no_match나 적은 결과가 "자료 없음"의 증명은 아닙니다.
  • 후보 → 원문 → 현재 실물 순서로 확인한 뒤에만 판단 근거로 씁니다. 요약이나 색인 행만으로 결론을 내리지 않습니다.
  • 운영 규칙이나 과거 실패와 관련된 일일 때만 lessons/index.md를 핵심어 2~3개로 grep하고, 통째로 읽지 않습니다.

5. 교훈 남기기

  • 실패 원인과 해결, 사용자 교정, 새로 확인된 사실이 생겼을 때만 교훈 원고를 만들고 WORKER 절차대로 작성합니다. python3 <로컬 운영 루트>/core/scripts/write-lesson.py --id <id> --body-file <JOB의 교훈 원고>를 사용하면 새 파일에 validation_status: candidate가 기록되고 색인은 자동 재생성됩니다. 기존 색인에 행을 수동 추가하지 않습니다. 응답서의 교훈: 칸에는 생성된 교훈 파일 경로를 적습니다.
  • 같은 교훈이 2회 이상 나오면 해당 스킬의 기존 항목을 일반화된 한 줄로 고칩니다. 절을 덧붙이지 않습니다.
  • JOB을 끝낼 때 result.md에서 교훈 파일을 링크합니다.
