통합 사례: 한 조건이 결과까지 가는 길

LUMA의 색과 문구 공간을 따라 다섯 분야의 연결과 수정 경로를 확인합니다.

요청을 한 문장으로 붙잡기색 조건 하나를 끝까지 따라가기정상 경로에서 남는 산출물오류가 난 층에서 수정하기공유할 자료를 새로 구성하기자신의 작업으로 옮겨 보기한 번 실행하고, 저장된 결과를 다시 읽기

요청을 한 문장으로 붙잡기

합성 의뢰는 ‘짙은 초록색 LUMA 램프의 가로 소개 이미지와 12초 영상을 만들고, 오른쪽에 문구를 읽을 공간을 남겨 달라’입니다. 완료 기준에는 제품 형태와 색, 이미지의 문구 공간, 영상의 총 길이와 장면 연결, 선택 구성과 검수 기록을 포함합니다.

이 조건은 여러 자료에 반복되지만 매번 다른 역할로 나타납니다. 작업에서는 완료 기준, 지식에서는 채택한 근거, 카탈로그에서는 선택 조건, 이미지에서는 배치, 영상에서는 샷과 편집 조건입니다. 같은 문장을 복사하는 대신 다음 구성요소가 쓸 수 있는 정보로 바뀝니다.

색 조건 하나를 끝까지 따라가기

이번 제작 명세를 색의 근거로 채택하면 파생 설명에 출처를 연결합니다. 이미지 명세에는 제품 색을 넣고 프롬프트 변환 결과에서 보존됐는지 확인합니다. 생성 결과를 고를 때 실제 색을 보고, 영상에서도 샷 사이에 같은 제품으로 인식되는지 확인합니다.

만약 영상 두 번째 샷만 색이 달라졌다면 원래 요청 전체를 다시 쓰기 전에 해당 샷의 참조, 프롬프트와 실행 구성을 찾습니다. 연결 기록이 있으면 수정 대상과 보존할 결과를 구분하기 쉬워집니다.

분야같은 조건이 바뀐 모습다음으로 넘기는 것
작업초록색 유지가 완료 기준검수 항목
지식이번 명세를 채택출처가 연결된 제품 조건
카탈로그제품/구도 요구에 맞는 구성선택 릴리스와 설정
이미지피사체 색 · 형태 · 배치채택 출력과 검수
영상샷별 색과 식별 일관성전체 재생 검수와 최종 파일

정상 경로에서 남는 산출물

정상 경로의 결과 묶음에는 명세, 채택한 근거, 선택한 구성, 생성 입력, 채택 결과, 검수 기록이 이어집니다. 실행 결과를 전달할 때 이 모든 문서를 한 화면에 펼칠 필요는 없습니다. 결과에서 필요한 근거로 이동할 수 있게 연결하면 됩니다.

이 예시에서 중요한 것은 문서 수보다 연결의 정확성입니다. 검수 보고서가 선택하지 않은 후보를 검사했다면 최종 결과의 근거로 쓰기 어렵습니다. 산출물 식별과 버전, 실제 파일에 대한 참조가 맞는지 확인하세요.

오류가 난 층에서 수정하기

형식 오류는 입력 필드에서, 잘못된 선택은 후보 조건에서, 시각적 오류는 생성 입력과 실제 결과에서 출발해 조사합니다. 예를 들어 문구 공간 선언이 빠졌다면 명세를 보완하고, 선언은 있는데 그림이 꽉 찼다면 구도 표현과 출력 검수를 살펴봅니다.

외부 요청 시간초과는 별도 경우입니다. 요청이 실행되지 않았는지, 실행됐지만 결과만 받지 못했는지 먼저 구별합니다. 작업 상태의 재시도와 미디어 서비스의 재시도는 다른 계층이므로 각각의 기존 결과를 확인한 뒤 이어갑니다.

공유할 자료를 새로 구성하기

공개할 때는 개인 자료를 담은 원본 디렉터리를 통째로 옮기기보다 공유 목적에 필요한 설명과 예시를 새로 구성합니다. 예시 출처와 식별자는 합성 값으로 만들고, 실제 자격증명이나 대화, 내부 경로를 포함하지 않도록 확인합니다.

본문뿐 아니라 코드 주석, 오류 메시지, JSON 메타데이터, 소스맵, 파일명과 링크에도 정보가 남을 수 있습니다. 공개 파일 목록을 기준으로 내용을 검토하고, 다운로드 가능한 모든 산출물도 같은 범위에 넣습니다. 사용자에게는 무엇을 공개했고 어떤 동작을 검증했는지 구체적인 결과로 전달합니다.

자신의 작업으로 옮겨 보기

자신의 요청을 골라 목표, 근거, 선택, 검증을 각각 한 문장으로 써 보세요. 다음에는 문장 사이에 전달할 구체적인 값을 하나씩 적습니다. 보고서 작성이라면 지식 출처와 문단 검수가 중요할 수 있고, 이미지 제작이라면 배치 조건과 픽셀 검수가 중요할 수 있습니다.

각 전달 값이 어디에서 생겼고 누가 읽으며 실패하면 어디로 돌아갈지 설명할 수 있다면 다섯 분야를 실제 판단에 적용한 것입니다. 참조 페이지에서는 용어와 공개 실습의 경계를 빠르게 확인할 수 있습니다.

한 번 실행하고, 저장된 결과를 다시 읽기

저장소 루트에서 Python 3.11 이상으로 설치한 뒤 아래 명령을 실행합니다. demo-output은 아직 존재하지 않는 새 디렉터리여야 합니다. 실습은 SQLite, 감사 이력, 지식 검색 결과, 이미지 바인딩 계획, SVG 스토리보드, 산출물 해시, 타임라인을 저장하고 DB를 다시 열어 완료 상태를 확인합니다.

실행 실습은 구조를 빠르게 확인하도록 2초와 3초의 두 샷으로 구성했습니다. 본문 LUMA의 12초·세 샷 기획과는 별개의 축소 실험입니다. report.json의 model_inference와 video_encoding은 false이며, 5초 타임라인은 계산된 편집 계획입니다. 실제 생성 영상 파일을 만들었다는 뜻은 아닙니다.

sh
python -m pip install -e .
p-hermes demo --output demo-output
p-hermes verify-artifact demo-output/artifact.json --root demo-output
python -m unittest discover -s tests -p "test_core*.py" -v
