검증과 변경 기록

완료 주장을 실제 결과와 대조하는 방법, 위험에 맞는 확인 깊이, 직접 수정의 복구점과 변경 이력을 설명합니다.

이 페이지의 로컬 경로와 확인 절차는 설치별 운영 좌표입니다. 공개 구현과 로컬 운영 확장의 범위는 구성과 범위에서 구분합니다.

검증은 기준과 실제 산출을 대조합니다

작업한 쪽은 지정된 완료조건과 수정 결과를 맞춰 보고, 필요한 테스트를 실행해 명령과 종료 결과를 기록합니다. 파일 산출은 실제 경로에서 열어 읽고, 필요한 경우 크기나 hash도 대조합니다. 테스트 성공만으로 내용이나 수용조건까지 확인했다고 판단하지 않습니다.

맡긴 쪽은 응답서에 보고된 결과를 그대로 받아들이지 않고, 적힌 산출 경로의 파일과 완료조건을 직접 대조합니다. 필수 산출, 선택 검증, 미확인 사항을 구분해 기록하면 완료와 부분 완료를 근거에 맞게 판정할 수 있습니다.

위험에 맞춰 확인 깊이를 정합니다

확인 범위는 변경의 영향과 되돌릴 수 있는 정도에 맞춥니다. 저위험 조사·권고는 근거를 읽고 논리와 요청 조건의 정합성을 확인합니다. 배포·설정 변경·제출·삭제처럼 영향이 큰 작업은 핵심 주장이나 결과를 독립적으로 다시 확인합니다.

  • 작은 로컬 변경은 수정 파일을 다시 읽고 요구사항과 diff를 대조합니다.
  • 코드 변경은 영향받는 호출 경로와 관련 테스트 결과를 확인합니다.
  • 외부 대상에 반영되는 변경은 로컬 파일 외에 원격 대상도 확인합니다.
  • 독립성이 필요한 검증은 변경을 수행한 사람과 분리된 읽기 전용 검토로 보강합니다.

실행이 성공했는지, 결과가 수용 기준을 충족했는지, 전달이 완료됐는지는 각각 다른 사실로 기록합니다. 확인하지 못한 항목은 성공으로 추정하지 않습니다.

외부 게시와 원격 반영을 다시 읽습니다

게시·전송은 external_publication 승인 범주에 해당합니다. 승인된 범위에서 작업한 뒤에는 로컬 산출과 게시 완료를 구분하고, 원격 대상에 새 요청을 보내 실제 상태·본문·첨부 등 필요한 결과를 다시 읽습니다. 게시 명령의 성공 출력이나 로컬 파일만으로 원격 반영을 판정하지 않습니다.

원격 read-back이 실패하거나 확인할 수 없다면 게시 완료로 기록하지 않습니다. 원격 변경을 반복하기 전에 기존 대상과 실행 영수증을 먼저 확인해 중복 전송을 막습니다.

직접 수정에는 되돌릴 원본을 둡니다

기존 파일을 직접 바꾸는 작업은 변경 전에 원본을 보관합니다. JOB이 있으면 해당 폴더의 pre-change/에 원본과 복구 자료를 두고, JOB 없이 하는 작은 수정은 대상 파일 옆에 .bak-<날짜> 사본을 둡니다.

백업은 자동으로 만료되는 임시 파일로 취급하지 않습니다. 목적과 복구 필요성을 확인할 때까지 보존하며, 원본으로 돌아갈 경로를 변경 기록에 남깁니다. 실제 백업·복원 방식은 해당 백업 스크립트와 전용 절차를 기준으로 합니다.

변경 기록은 이유와 복구점을 연결합니다

직접 수정 기록은 orchestration/records/manager-actions.md에 한 줄로 추가합니다. 기록은 시각, 수행 주체, 무엇을 왜 바꿨는지, 대상 파일, 백업 경로를 연결합니다. 예를 들면 다음 항목을 확인할 수 있어야 합니다.

  • 변경이 일어난 시각과 수행 주체
  • 변경 목적과 실제로 바꾼 파일
  • pre-change/ 또는 .bak-<날짜> 복구 위치

기록은 무엇을 바꿨는지 추적하는 수단이며 승인이나 검증을 대신하지 않습니다. JOB 단위의 작업은 실행·검증·결과를 해당 JOB 기록에 남기고, 별도 직접 변경이 있으면 변경 기록 형식에 맞춰 보충합니다.
