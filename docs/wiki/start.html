좋은 결과에는 판단의 흔적이 있습니다

작은 램프 LUMA의 소개 이미지와 짧은 영상을 만든다고 생각해 봅시다. 예쁜 그림을 얻은 뒤에도 질문은 남습니다. 제품 색은 어디에서 확인했을까요? 왜 이 모델과 구성을 골랐을까요? 영상의 마지막 장면은 첫 장면과 같은 제품일까요?

p-hermes v2는 이런 질문을 작업, 지식, 카탈로그, 이미지, 영상이라는 다섯 책임으로 나누어 설명합니다. 목표와 판단, 실행 입력과 산출물, 검증 결과를 이어 두면 결과를 고치거나 같은 조건으로 다시 시도할 때 출발점을 찾을 수 있습니다.

다섯 분야가 나누어 맡는 일

작업은 목표와 진행 상태를 관리하고, 지식은 판단에 사용한 근거를 다룹니다. 카탈로그는 사용할 수 있는 자원의 구성과 조건을 관리합니다. 이미지와 영상은 그 조건을 각각 공간과 시간의 표현으로 바꿉니다.

읽는 순서는 전체 지도를 익히기 위한 것입니다. 실제 요청은 필요한 분야만 사용합니다. 문서를 조사하는 일은 미디어 생성을 거치지 않아도 되고, 텍스트에서 시작하는 영상은 이미지 생성 단계를 먼저 수행하지 않아도 됩니다.

먼저 이해하고, 필요한 깊이로 내려가기

각 분야의 앞부분은 왜 필요한지와 어떤 정보가 오가는지를 설명합니다. 그다음에는 실제 Hermes 구현에서 확인한 구성요소와 계약을 살펴봅니다. 마지막에는 실패를 구별하는 방법과 공개 실습으로 확인할 수 있는 범위를 다룹니다.

처음 읽는다면 작업에서 영상까지 순서대로 읽은 뒤 통합 사례로 돌아오세요. 구현을 검토하는 독자는 관심 분야의 기술 절과 참조 페이지로 바로 이동해도 됩니다. 발표 자료는 같은 주제를 한 화면의 주장과 도해로 압축하며, 이 위키가 상세 설명을 보완합니다.

운영 구조와 공개 실습의 관계

이 위키의 운영 구조 설명은 2026년 9월 10일 관련 소스를 읽어 확인한 내용을 바탕으로 새로 작성했습니다. 함수와 필드가 존재한다는 사실, 함수가 특정 검사를 한다는 사실, 실제 서비스에서 전체 실행이 성공했다는 사실은 서로 다른 수준의 근거입니다.

공개 저장소의 실습은 합성 데이터와 독립적으로 작성한 코드로 핵심 계약을 탐구하도록 구성합니다. LUMA와 문서의 후보·출처·샷은 교육용 예시입니다. 개인 대화, 실제 작업 산출물, 내부 접속 정보는 실습의 입력으로 사용하지 않습니다.

이 자료에서 확인하는 것

실제 구조를 설명하고 공개 코드의 동작을 시험합니다. GPU 생성 품질, 외부 서비스 가용성, 운영 환경 전체 설치 성공은 각각 별도 실행 증거가 필요합니다.

세 가지 말을 먼저 맞춥니다

계약은 다음 구성요소가 입력을 이해하기 위해 지켜야 하는 조건입니다. 예를 들어 영상 샷의 길이는 양수여야 하고, 첫 프레임을 사용하는 모드는 그 참조가 있어야 합니다. 계약을 검사하면 입력의 빠진 부분을 실행 전에 찾을 수 있습니다.

산출물은 결과 파일과 그 결과를 설명하는 기록을 뜻합니다. 근거는 판단을 뒷받침하는 관측이나 자료입니다. 검증 보고서도 산출물이지만, 어떤 입력과 어떤 검사로 얻었는지를 알아야 완료의 근거로 사용할 수 있습니다.
