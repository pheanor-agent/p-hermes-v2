자료를 찾았을 때 판단도 함께 남깁니다

LUMA의 오래된 소개 문서는 색을 흰색이라고 하고, 이번 제작에 제공한 명세는 짙은 초록이라고 합시다. 두 문장을 저장하는 것만으로는 다음 사람이 무엇을 써야 할지 알 수 없습니다. 이번 작업에 어떤 출처를 채택했고 왜 그랬는지를 남겨야 합니다.

지식 관리는 정보를 모으는 일과 재사용을 허용하는 판단을 연결합니다. 원본 자료는 근거를 보존하고, 등록 메타데이터는 종류·권위·상태를 설명하며, 인덱스는 필요한 항목을 찾게 합니다. 각각의 역할을 분리하면 갱신해야 할 곳도 명확해집니다.

원문, 등록 정보, 인덱스의 역할

운영 knowledge-register의 validate_metadata는 artifact_id, knowledge_type, source_job, authority, priority, registration_status를 검사합니다. authority가 derived이면 canonical_source도 요구합니다. 이 검사는 등록 정보가 정해진 형식을 갖추는지 확인합니다.

등록 정보의 형식이 맞는다고 원문의 주장이 참이 되거나 출처가 실제 존재한다고 증명되는 것은 아닙니다. 파생 지식이 원문을 어떻게 요약했는지, 사용 권한이 있는지, 현재 요청에 맞는지는 별도 검토의 몫입니다. 공개 예시에서는 개인 작업 참조를 가져오는 대신 합성 출처로 이 관계를 표현합니다.

충돌에서 채택된 근거까지

합성 예시에서 source-a는 지난 소개안, source-b는 이번 제작 명세입니다. 두 자료가 같은 속성에 다른 값을 제공하면 곧바로 한쪽을 지우기보다 적용 범위를 확인합니다. 이번 작업의 제품 명세를 우선한다는 판단이 확인되면 초록색을 채택하고 source-b를 연결합니다.

이 결과를 새로운 설명문으로 정리할 때는 파생 정보임을 남깁니다. 이후 source-b가 바뀌면 파생 설명도 재검토 대상이 됩니다. 검색 결과를 최신으로 만들려면 원문 변경, 등록 상태 갱신, 인덱스 반영이 어느 단계까지 끝났는지 따로 확인해야 합니다.

등록과 일일 수집은 별도 경로입니다

knowledge-register는 메타데이터를 검사하고 지정 디렉터리에 등록 파일을 만드는 작은 진입점입니다. 반면 daily-knowledge-process는 여러 자료를 모으고 세션 처리기, 작업 산출물 처리기, generate-llms를 호출하는 운영 파이프라인입니다. 현재 소스에서 이 호출 관계를 확인했습니다.

별도의 knowledge-process는 요약 자리표시자를 만드는 경로를 포함합니다. 이를 완성된 AI 요약 엔진으로 소개하지 않습니다. 작업 완료 hook도 별도의 git 관리 후처리이므로 ‘작업 완료 즉시 지식 승격과 검색까지 자동 완료’라는 연결은 현재 읽은 근거만으로 성립하지 않습니다.

등록 성공 뒤에도 확인할 것이 남습니다

메타데이터 검사, 파일 쓰기, 인덱스 갱신, 검색은 서로 다른 실패 지점을 가집니다. 예를 들어 등록 파일이 있어도 인덱스 갱신이 실패하면 독자가 찾지 못할 수 있습니다. 검색 결과가 나온다고 오래된 주장과 새 주장의 충돌이 해결된 것도 아닙니다.

운영 등록기의 원본 구현은 식별자를 파일명에 사용하고 중복 존재를 검사한 뒤 쓰는 방식입니다. 범용 공개 구현에서는 안전한 식별자와 저장 경계, 동시 등록 충돌을 별도로 다뤄야 합니다. 검사 모드가 형식만 확인하는지, 중복이나 실제 쓰기까지 확인하는지도 구분해서 읽으세요.

지식 검수는 질문을 재현하는 일입니다

검수할 때는 ‘이번 소개 이미지의 제품 색은 무엇인가?’라는 질문으로 시작해 봅시다. 기대 답은 초록색이며 이번 명세를 가리켜야 합니다. 원문을 바꾼 후 같은 질문을 반복하면 출처와 파생 설명, 인덱스 중 어디가 뒤처졌는지 확인할 수 있습니다.

운영 환경의 검색 소비자 전체를 이 문서에서 실행한 것은 아닙니다. 공개 실습은 메타데이터와 출처 관계의 일부를 확인합니다. 지식에서 얻은 조건은 다음 장의 카탈로그에서 ‘어떤 구성을 사용할 것인가’를 결정하는 입력이 됩니다.

공개 실습: 등록, 검색, 퇴역을 직접 연결하기

공개 Store.register_knowledge는 id, title, body, source_ref, license_ref와 public: true를 받습니다. 운영 등록기와 같은 스키마를 복제하지 않고 공개 실습에 필요한 필드를 따로 정의했습니다. 선언만으로 본문의 개인정보나 권리가 자동 검증되는 것은 아니므로 입력은 직접 검토한 합성 자료를 사용합니다.

search는 활성 자료의 제목과 본문을 대소문자 구분 없는 부분 문자열로 찾습니다. 의미 검색이나 자동 요약은 수행하지 않습니다. retire_knowledge 뒤에 같은 질의를 실행하면 해당 자료가 결과에서 사라지므로 상태 변경과 검색 결과의 관계를 직접 관찰할 수 있습니다.

python
from p_hermes.store import Store

with Store("knowledge-lesson.sqlite3") as store:
    store.register_knowledge({
        "id": "lamp-note", "title": "LUMA 배치",
        "body": "램프는 왼쪽에 두고 오른쪽 문구 공간을 남긴다.",
        "source_ref": "synthetic:brief",
        "license_ref": "CC0-1.0", "public": True
    })
    print(len(store.search("문구")))  # 1
    store.retire_knowledge("lamp-note")
    print(len(store.search("문구")))  # 0
