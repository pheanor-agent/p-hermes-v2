참조: 계약과 검증 범위 빠르게 찾기

주요 용어, 운영 구성요소와 확인 범위를 한곳에서 비교합니다.

핵심 용어운영 소스에서 확인한 책임검사 결과를 읽는 방법이 문서의 구성 원칙공개 코드 진입점구현 사실의 출처를 구분해서 읽기

핵심 용어

이 표는 본문에서 설명한 용어를 다시 찾기 위한 참조입니다. 새로운 작업을 시작할 때는 용어를 외우기보다 어떤 판단을 기록하고 어떤 입력을 전달할지 먼저 생각하세요.

운영 소스에서 확인한 책임

아래 이름은 운영 구조의 어느 부분을 설명하는지 찾기 위한 것입니다. 내부 절대경로와 개인 설정은 공개하지 않습니다. 공개 저장소의 독립 실습 코드가 이 운영 파일 전부를 설치하거나 대체하는 것은 아닙니다.

검사 결과를 읽는 방법

PASS라는 한 단어보다 검사 대상과 관측 결과를 함께 읽으세요. 스키마 검사는 필드의 형식과 관계, 참조 검사는 식별과 연결, 실행 검사는 실제 프로세스와 파일, 미디어 검수는 화면과 시간을 다룹니다.

소스 정적 확인은 구현에 어떤 조건과 호출이 있는지 보여줍니다. 합성 테스트는 선택한 입력에서 공개 코드가 어떻게 반응하는지 보여줍니다. 실제 외부 실행은 특정 환경과 시점에서의 결과를 보여줍니다. 좁은 검사의 성공을 전체 시스템의 성공으로 확대하지 않습니다.

근거증명하는 범위추가로 확인할 범위
필드 검사 성공입력이 해당 검사 조건을 만족실제 자산 · 권리 · 의미
해시 일치같은 규칙으로 비교한 내용의 일치내용의 정확성 · 호환성
health=healthy기록된 시점의 상태 선언현재 환경과 실행 결과
샷 validator 성공입력 모드와 필수 계약모델의 실제 지원 · 영상 품질
실습 테스트 성공해당 테스트 입력의 공개 코드 동작미포함 경로 · 운영 통합

이 문서의 구성 원칙

개념 설명, 따라 해 보는 실습, 필드 참조는 읽는 목적이 다르므로 연결된 별도 단위로 제공합니다. Diátaxis의 문서 목적 구분을 편집에 참고했습니다. 이는 정보 구조 참고이며 Hermes 구현의 사실 근거로 사용하지 않았습니다.

독자가 이미 아는 것과 새로 알아야 할 것의 간극을 줄이기 위해 먼저 사례와 역할을 설명하고 기술 이름을 소개합니다. Google Technical Writing의 독자 중심 지침을 참고했습니다. 코드와 운영 사실은 현재 확인한 소스와 공개 저장소의 검증 결과에 맞추어 읽어야 합니다.

공개 코드 진입점

이 표는 저장소의 독립 공개 구현에 대응합니다. 설치 후 p-hermes --help로 명령을 확인할 수 있습니다. 출력 파일은 새 경로로 지정하며 기존 실습 결과와 구별합니다.

구현 사실의 출처를 구분해서 읽기

운영 구조는 2026년 9월 10일 관련 구현을 읽어 확인한 책임과 조건을 새로 서술했습니다. 개인 설정과 원본 작업 데이터가 포함된 운영 파일은 배포하지 않으므로 이 페이지의 GitHub 링크는 별도로 작성한 공개 구현을 가리킵니다. 함수 이름이 같거나 비슷하더라도 공개 소스를 운영 원본의 직접 인용 근거로 바꾸어 읽지 마세요.

작업의 그래프 전이와 revision 비교, 지식 등록기의 필드 조건, 카탈로그의 실행 입력 변환, 이미지 컴파일 결과 구조, 영상 샷 검증은 각각 해당 분야의 기술 절에 확인 범위를 적었습니다. 호출 존재와 입력 검사에 대한 설명을 외부 서비스의 실행 성공으로 확대하지 않습니다. 공개 구현은 링크된 소스와 테스트를 직접 실행해 검토할 수 있습니다.
