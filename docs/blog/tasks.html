작업 상태 — 왜 진행과 승인을 나눠서 관리하는가

작업의 현재 상황과 다음 행동의 허용을 분리하고, 변경·중단·재개를 확인 가능한 근거와 함께 다루는 이유를 설명합니다.

작업을 안전하게 진행하려면 무엇을 관리해야 하는가

작업을 이어 가려면 현재 상황, 다음 단계, 실행 허용, 완료 근거를 서로 다른 질문으로 관리해야 합니다.

작업은 시작 버튼을 누른 뒤 곧바로 완료되는 한 번의 동작이 아닙니다. 계획을 세우고, 진행 상황을 확인하고, 실제 실행을 허용하고, 결과를 검수하며, 필요하면 중단하거나 다시 이어 갑니다. 우리는 이 전체 생애주기를 먼저 보고 작업 관리의 역할을 정했습니다.

이 과정에서는 ‘지금 어디까지 왔는가’와 ‘다음 행동을 해도 되는가’가 자주 달라집니다. 결과를 기다리는 중일 수도 있고, 계획은 준비됐지만 검토가 끝나지 않았을 수도 있습니다. 완료 역시 파일 하나가 생겼다는 이유만으로 판단하지 않고, 필요한 결과와 검수 근거가 갖춰졌는지를 함께 봅니다.

그래서 작업 기록은 단순한 진행 표시가 아니라 다음 판단의 출발점입니다. 뒤에서는 현재 상황과 행동 허용을 왜 나누는지, 여러 변경이 겹칠 때 무엇을 확인해야 하는지, 결과가 불명확할 때 어디서 다시 시작해야 하는지를 차례로 살펴봅니다.

작업의 현재 상태와 다음 행동의 허용을 왜 나누는가

현재 상황을 설명하는 기록과 다음 행동을 허용하는 판단은 목적이 다릅니다.

작업이 정상적으로 진행되고 있다고 해서 언제나 다음 실행을 시작해도 되는 것은 아닙니다. 검토가 끝나지 않았거나, 필요한 근거가 바뀌었거나, 계획의 범위가 달라졌다면 진행 자체에는 문제가 없어도 실행은 멈춰야 합니다. 우리는 현재를 설명하는 정보와 앞으로의 행동을 허용하는 판단을 분리합니다.

이 구분이 있으면 같은 작업에서도 ‘무엇이 사실인가’와 ‘무엇을 해도 되는가’를 따로 확인할 수 있습니다. 현재 상황은 작업의 위치를 설명하고, 허용은 다음 행동의 범위를 제한합니다. 둘을 하나의 표시로 합치면 진행이 정상이라는 이유만으로 승인되지 않은 행동까지 이어질 수 있습니다.

같은 제품의 소개 영상 계획이 준비됐더라도 장면 수나 사용 자원이 검토 중이라면 제작을 시작하지 않는 편이 안전합니다. 반대로 이미 허용된 범위 안에서 결과를 기다리는 중이라면 새 승인을 반복해서 요구할 필요도 없습니다. 중요한 것은 각 판단이 답하는 질문을 섞지 않는 것입니다.

동시에 바뀌고 계획이 달라질 때 무엇이 깨지는가

내가 읽은 뒤 작업이 달라졌는지 확인하지 않으면 안전한 변경이라고 볼 수 없습니다.

같은 작업을 두 사람이 같은 시점에 읽고 각자 수정을 시작했다고 생각해 봅시다. 한쪽이 먼저 판단을 바꾸었는데 다른 쪽이 예전 내용을 기준으로 저장하면 앞선 결정이 조용히 덮일 수 있습니다. 우리는 저장 직전에 ‘내가 읽은 뒤 바뀐 것이 없는가’를 확인하는 원칙을 둡니다.

변경이 발견되면 같은 요청을 그대로 다시 밀어 넣는 대신 최신 내용을 다시 읽어야 합니다. 이미 달라진 조건에서도 원래 하려던 수정이 여전히 맞는지 새로 판단해야 하기 때문입니다. 충돌을 단순한 저장 오류가 아니라 오래된 판단을 감지한 신호로 보는 이유입니다.

계획이 바뀌는 경우도 같은 원리로 다룹니다. 세 장면으로 검토했던 영상을 다섯 장면으로 바꾸거나 사용 자원을 교체했다면, 이전에 허용했던 범위가 새 계획에도 그대로 적용된다고 가정할 수 없습니다. 변경의 의미를 다시 보고 필요한 경우 실행 허용도 다시 확인합니다.

중단되거나 결과가 애매할 때 어떻게 안전하게 끝내는가

모르는 상태에서 재실행하지 않고, 마지막으로 확인된 사실에서 이어 가야 합니다.

외부 실행을 요청한 뒤 연결이 끊겼다고 해서 바로 실패라고 단정할 수는 없습니다. 실행이 시작되지 않았을 수도 있고, 이미 끝났지만 응답만 돌아오지 않았을 수도 있습니다. 이 둘을 같은 실패로 취급하면 이미 끝난 작업을 다시 실행해 중복 결과나 비용을 만들 수 있습니다.

우리는 먼저 기존 실행이나 저장된 결과를 조회해 무엇이 실제로 확인됐는지 찾습니다. 성공, 실패, 아직 모름을 구분한 뒤 마지막으로 확실한 사실에서 다음 행동을 결정합니다. 복구는 추측을 채우는 과정이 아니라 모르는 부분을 줄이는 과정입니다.

완료 판단도 같은 태도를 따릅니다. 결과 파일이 존재하는지, 실제 내용이 열리고 사용할 수 있는지, 처음 정한 요구를 만족하는지까지 확인해야 합니다. 작업을 안전하게 끝낸다는 말은 ‘무언가가 생겼다’가 아니라 ‘완료라고 말할 근거가 모였다’는 뜻입니다.
