필요한 모델과 워크플로우 고르기

생성 작업에서 “어떤 모델을 쓸 것인가”는 중요한 질문이지만 그것만으로는 실제 실행을 결정하기 어렵습니다.

하나의 생성 후보에는 모델뿐 아니라 워크플로우, 실행 환경, 버전, 필요한 추가 자원과 현재 사용 가능 상태가 함께 영향을 줍니다. 어떤 모델이 특정 용도에 적합하더라도 현재 환경에서 실행할 수 없거나, 연결된 워크플로우가 다른 버전을 요구할 수 있습니다.

반대로 하나의 자원이 여러 용도에 사용될 수도 있고, 같은 용도에 여러 후보가 존재할 수도 있습니다. 그래서 카탈로그를 단순한 모델 목록으로 보면 실제 선택 과정에서 필요한 정보를 놓치기 쉽습니다.

중요한 것은 이름보다 이번 작업에서 함께 사용해야 하는 조건의 묶음입니다.

선택은 요청의 조건에서 시작합니다

후보를 고를 때 먼저 볼 것은 인지도나 한 가지 성능 수치가 아니라 현재 작업의 요구입니다.

후보를 고를 때 먼저 볼 것은 인지도나 한 가지 성능 수치가 아니라 현재 작업의 요구입니다. 어떤 입력을 받아야 하는지, 필요한 크기나 형식이 있는지, 사용할 수 있는 실행 환경은 무엇인지, 현재 확인된 상태는 어떤지를 기준으로 후보를 줄일 수 있습니다.

후보가 하나라면 그 이유를 설명할 수 있어야 하고, 여러 개라면 무엇이 선택을 가르는 조건인지 확인해야 합니다. 반대로 조건을 만족하는 후보가 없다면 임의로 가까운 것을 고르기보다 어떤 조건이 부족한지 드러내는 편이 낫습니다.

선택 이유와 제외 이유를 남겨 두면 요구가 바뀌었을 때 전체 조사를 반복하지 않고 필요한 후보만 다시 비교할 수 있습니다.

선택한 자원이 실제 실행에 반영되어야 합니다

카탈로그에서 적절한 후보를 골라도 실제 실행 단계가 다른 모델이나 다른 워크플로우를 사용하면 선택 과정은 의미가 없어집니다.

카탈로그에서 적절한 후보를 골라도 실제 실행 단계가 다른 모델이나 다른 워크플로우를 사용하면 선택 과정은 의미가 없어집니다. 그래서 선택된 자원이 실행 입력으로 제대로 전달되는지 확인하는 단계가 필요합니다.

공개 실습에서는 이미지 생성에 필요한 기본 입력이 미리 정해진 위치에 올바르게 연결되는지 확인하는 예를 보여 줍니다. 이 실습의 목적은 좋은 이미지를 만드는 것이 아니라 선택한 구성과 실제 실행 입력이 어긋나지 않는지를 확인하는 데 있습니다.
