지식은 에이전트의 모든 동작 밑에 있습니다

에이전트의 지식02 / 11

지식은 맥락 창에 들어와야 쓸 수 있습니다

언어 모델은 이 시스템의 지난 실패나 오늘 바뀐 규칙을 스스로 알지 못합니다. 필요한 기록을 찾아 맥락 창에 넣어 줘야 씁니다.

그래서 기록을 남기는 것만큼 필요할 때 찾아 넣는 길이 중요합니다.

검색의 한계03 / 11

검색은 후보를 줄 뿐, 놓치는 것도 있습니다

단어 중심 검색은 같은 단어가 들어간 기록은 잘 찾지만, 뜻은 같고 표현이 다른 기록(예: timeout)은 놓칠 수 있습니다.

그래서 검색 결과는 언제나 후보로 다루고, 판단 전에 원문과 현재 파일을 직접 확인합니다.

작업 앞뒤05 / 11

작업 앞뒤로는 교훈이 순환합니다

작업이라는 단위에서 보면 지식은 원을 그립니다. 작업 전에는 관련 교훈과 결정을 모아 읽고, 작업 후에는 다시 쓸 만한 것만 남기며, 다음 날 요약으로 모입니다.

이 원은 지식이 쓰이는 여러 자리 중 하나입니다. 규칙·기억·스킬은 작업이 아니어도 늘 읽힙니다.

작업 전06 / 11

context pack이 관련 교훈과 결정을 먼저 모아 줍니다

워커 요청은 dispatcher가 context pack을 자동으로 만들고, 매니저가 직접 JOB을 시작할 때도 먼저 실행합니다(POLICY (a-3) 9).

운영 규칙이나 과거 실패와 관련된 일일 때만 lessons/index.md를 핵심어 2~3개로 grep합니다. 통째로 읽지 않습니다.

찾기07 / 11

후보를 좁히고, 원문을 읽고, 실물로 확인합니다

검색 결과는 후보입니다. 단어 중심 검색은 의미상 맞는 자료를 놓칠 수 있고, 빈 결과가 자료 없음의 증명도 아닙니다.

후보 → 원문 → 현재 실물, 세 번째 단계에서야 판단 근거가 됩니다.

KEY IDEA

적지 않은 교훈은 다시 반복된다

같은 실패를 두 번 겪으면, 그 교훈은 절차로 승격됩니다.

승격10 / 11

같은 교훈이 두 번 나오면 스킬을 고칩니다

승격은 새 절을 덧붙이는 것이 아니라 기존 항목을 한 줄로 일반화하는 것입니다. 스킬 본문은 8KB 이하를 유지합니다.

그래서 스킬은 늘어나지 않고, 실제로 반복된 교훈만 절차에 반영됩니다.
