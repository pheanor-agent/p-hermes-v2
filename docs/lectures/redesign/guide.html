검사 가능한 선택으로.

“작은 책상용 램프를 소개하는 이미지와 짧은 영상 기획을 만들어 줘.” 이 한 문장에서 시작합니다. 목표는 예쁜 한 장을 만드는 데 그치지 않고, 같은 제품의 색과 형태를 유지하며 문구 공간까지 확보하는 것입니다.

교육용 일러스트 · 목표 예시. LUMA는 가상의 제품명입니다. 제품명세·후보·샷 기획은 합성이며 실제 브랜드, 실제품 성능, AI 생성 미디어를 나타내지 않습니다. SVG는 이 강의를 위해 작성한 그림입니다.

1. 먼저 결과의 기준을 고정한다

제품은 청록색, 납작한 헤드, 가는 지지대, 타원 받침으로 정의합니다. 소개 문구를 넣을 공간이 필요하고 세 샷에서 색과 형태가 같아야 합니다. “전경 → 헤드와 빛의 근접 구도 → 위에서 본 사용 공간”은 같은 제품을 다른 시점에서 보여 주는 샷 기획입니다. 실제 영상은 생성하지 않습니다.

2. 다섯 분야는 서로 다른 판단을 맡는다

브라우저에서 단계를 누르면 fixtures.json의 해당 입력·처리·출력을 표시합니다. 운영 시스템이 작업을 실제 실행하는 것은 아닙니다. 아래는 클릭 없이 읽는 전체 설명입니다.

01 작업 — 어디까지 해도 될까?
입력: 램프 소개 이미지와 짧은 영상 기획 요청.
처리: 목표와 승인 범위를 나누고, 허용된 제작과 대기할 실행을 구분합니다.
출력: 교육용 컷·3샷 기획은 허용. 실제 미디어 생성과 운영 실행은 대기합니다.
02 지식 — 무엇을 바꾸면 안 될까?
입력: 합성 제품명세 LUMA, 청록, 납작한 헤드·가는 지지대·타원 받침.
처리: 출처와 조건을 묶고 명세에 없는 성능은 덧붙이지 않습니다.
출력: 합성 brief, 제품 색·형태, 문구 공간, 샷 간 동일성의 근거 묶음.
03 카탈로그 — 어떤 구성이 조건에 맞을까?
입력: 소개 이미지 목적과 문구 공간 필수 조건, 교육용 후보 A·B.
처리: 후보 한 개를 선택하고 template·variant·release ID를 기록합니다.
출력: 기본 B의 식별자는 desk-launch / title-space / lesson-r1, text_space=true입니다. A는 close-up, text_space=false입니다.
04 이미지 — 제품과 문구는 어디에 놓을까?
입력: 고정 제품명세와 현재 선택한 레이아웃.
처리: 제품 영역과 타이틀 영역을 나눠 한 장의 구도를 기획합니다.
출력: B는 좌측 상단에 문구 공간, 우측에 제품을 배치합니다. A는 제품을 크게 배치해 문구 영역이 없습니다. 실제 생성물은 아닙니다.
05 영상 — 다른 샷에서도 같은 제품일까?
입력: 같은 brief, 색·형태 기준, 선택 레이아웃.
처리: 전경·근접·탑뷰를 기획하고 제품의 동일성을 고정합니다.
출력: 01 책상 전경, 02 헤드와 빛, 03 사용 공간의 세 샷 계획. 실제 영상 생성은 실행하지 않습니다.

3. 취향이 아니라 선언된 조건을 검사한다

A의 근접 구도가 미적으로 틀렸다는 뜻은 아닙니다. 이 과제는 required_text_space=true이므로 문구 영역이 없는 A가 조건을 충족하지 못하는 것입니다.

안정적 오류 코드검사 규칙
COUNTselected_count는 정확히 숫자 1. 문자열 "1"과 boolean true는 불허.
TEMPLATE_IDtemplate_id는 trim 후 비어 있지 않은 문자열.
VARIANT_IDvariant_id는 trim 후 비어 있지 않은 문자열.
RELEASE_IDrelease_id는 trim 후 비어 있지 않은 문자열.
TEXT_SPACErequired_text_space가 true이면 variant.text_space도 정확히 boolean true.

오류는 위 표 순서대로 반환합니다. 문자열의 앞뒤 공백만으로 ID를 실패시키지는 않으며, 공백만 있는 ID는 실패합니다. 입력을 변경하지 않는 순수 함수 validateFixture(value)를 브라우저 UI와 Node 검사에서 공통으로 사용합니다.

기본 입력과 예상 결과

{
  "selected_count": 1,
  "template_id": "desk-launch",
  "variant_id": "title-space",
  "release_id": "lesson-r1",
  "required_text_space": true,
  "variant": { "text_space": true }
}
예상: { "ok": true, "errors": [] }

이 정적 문서의 예상 결과는 실시간 실행 증거가 아닙니다. 상호작용 화면은 표시하는 JSON 객체 자체를 함수에 전달한 결과를 PASS 또는 FAIL로 표시합니다. 선언된 공통 테스트 입력과 기대값은 fixtures.json의 testVectors에서 확인할 수 있습니다.

  • A를 선택하면 TEXT_SPACE. B를 선택하면 문구 공간 오류가 해소됩니다.
  • “선택 수 2로”는 COUNT를 주입하며, 다시 누르면 숫자 1로 복원합니다.
  • “release ID 누락”은 RELEASE_ID를 주입하며, 다시 누르면 현재 후보의 release ID를 복원합니다.
  • 오류 주입은 누적됩니다. 후보를 바꿔도 개수·누락 오류는 유지되어 원인을 하나씩 확인할 수 있습니다.
  • “초기화”는 기본 B, 선택 수 1, 세 ID와 문구 공간 값을 모두 복원합니다.

PASS의 한계: 이 fixture의 다섯 규칙만 통과했다는 뜻입니다. 실제 ID가 운영 카탈로그에 존재하는지, 미디어가 생성되었는지, 제품이 같은지까지 검증하지 않습니다. 공개 상태와 실행 검증 상태도 서로 다른 개념입니다.

탐색과 정적 대체

상단 01·02·03 링크로 이동합니다. PageDown·PageUp은 화면을 이동하며, 단계 버튼에서는 좌우 화살표로 실제 키보드 초점을 옮기고 Enter·Space로 선택합니다. Tab은 모든 링크·버튼·선택 상자를 순서대로 방문합니다. 자동 재생이나 자동 이동은 없습니다.

내부 화면의 레이아웃 선택은 검증 화면에 이어집니다. 같은 페이지 내 앞뒤 이동에는 선택을 유지하지만 새로고침, 새 탭, 직접 hash 진입은 결정적 기본 B로 시작합니다. localStorage나 쿠키에 저장하지 않습니다.

JavaScript가 없거나 fixture 로딩에 실패하면 세 화면을 선형으로 읽을 수 있습니다. 모든 입력·처리·출력은 내부 화면의 “다섯 단계 전체 읽기”에도 있으며, 이 문서는 JavaScript 없이 전체 내용을 제공합니다. 인쇄는 모든 화면과 정적 설명을 펼칩니다. 좁은 화면과 확대에서는 세로 스크롤로 내용을 읽습니다.

통신은 같은 출처의 fixtures.json과 정적 SVG·CSS·JS 로딩뿐입니다. 외부 폰트·이미지·분석 스크립트·생성 API는 사용하지 않습니다.

근거를 고정하고,
선택을 기록하고,
결과를 검증한다.

작업·지식·카탈로그·이미지·영상이라는 분류의 목적은 결국 하나입니다. 막연한 요청을, 이유를 설명하고 잘못된 선택을 찾아낼 수 있는 결과로 바꾸는 것입니다.
