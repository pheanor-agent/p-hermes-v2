01 / 작업

어디까지 해도 될까?

입력
작은 책상용 램프 소개 이미지 + 짧은 영상 기획 요청
처리
목표를 나누고, 승인된 제작과 대기할 실행을 구분한다.
출력
허용: 교육용 제품 컷·3샷 기획. 대기: 실제 미디어 생성·운영 실행.

선택 B · title-space · 문구 공간 있음

작업은 범위를, 지식은 근거를, 카탈로그는 자산을.
이미지는 구도를, 영상은 연속성을 맡습니다.

이 선택, 조건에 맞을까? ↗
다섯 단계 전체 읽기 · 정적 대체
작업
입력: 램프 소개 요청 → 처리: 목표·승인 범위 구분 → 출력: 교육용 컷·3샷 계획 허용, 실제 생성 대기.
지식
입력: 합성 제품명세 → 처리: 출처와 조건 추출 → 출력: 청록·납작한 헤드·가는 지지대·타원 받침, 문구 공간과 동일성 근거 묶음.
카탈로그
입력: 소개 이미지 목적, 문구 공간 필수 → 처리: 후보 A 또는 B 한 개 선택 → 출력: desk-launch / title-space / lesson-r1 (기본 B).
이미지
입력: 명세와 선택 레이아웃 → 처리: 제품·타이틀 영역 배치 → 출력: B는 좌측 상단 문구 여백을 확보한 구도. A는 여백 없음.
영상
입력: 같은 brief·제품 기준 → 처리: 전경·근접·탑뷰 순서 기획 → 출력: 3샷 계획, 청록색과 형태 유지. 실제 생성 영상 아님.
교육용 단계 전환 · 실운영 orchestration 아님다섯 단계 상세 ↗

03 / MAKE IT FAIL. UNDERSTAND WHY.

선택을 바꾸면,
검사 결과도 바뀐다.

취향을 채점하지 않습니다.
“문구 공간 필수”를 검사합니다.

같은 제품 / 다른 구성직접 선택 ↓

교육용 구성 비교 · 실제 생성물 아님

다른 오류도 확인

초기화: B · 1개 · 모든 ID 복원

LIVE FIXTURE데이터 ↗

  "selected_count": 1,
  "template_id": "desk-launch",
  "variant_id": "title-space",
  "release_id": "lesson-r1",
  "required_text_space": true,
  "variant": { "text_space": true }
}
정적 예시 · 아직 실행하지 않음

기본 B는 선언된 조건에 맞습니다. JavaScript가 활성화되면 위 JSON을 실제 검사합니다.

PASS는 이 fixture의 조건 검사만 의미합니다.
미디어 생성·운영 카탈로그의 성공 증거가 아닙니다.

근거를 고정하고, 선택을 기록하고, 결과를 검증한다.검사 규칙 읽기 ↗

클릭 없이 읽는 검사

B: 문구 공간 true, 선택 수 1, ID 세 개가 있으므로 정상 조건. A: 문구 공간 false → TEXT_SPACE. 선택 수 2 → COUNT. release_id 없음 → RELEASE_ID. 정적 설명이며 실행 결과가 아닙니다.

JavaScript 없이도 세 화면을 순서대로 읽을 수 있습니다. 전체 설명: 정적 읽기.
