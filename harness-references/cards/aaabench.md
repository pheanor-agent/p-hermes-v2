## 자체 요약

Unreal Engine Editor를 MCP로 제어해 coding agent가 장기 open-world game 제작을 수행하는 benchmark/harness 사례다. agent runner, session resume, crash recovery, viewport 검사와 제작 단계 gate를 포함한다고 기존 source review가 기록한다.

## 상세 정리
### 핵심 주장
- 이 저장소는 완성된 게임이 아니라, 코딩 에이전트가 장시간 게임 콘텐츠를 만들도록 묶은 벤치마크형 하네스다. 에디터는 외부 도구 연결(MCP)로 조작되고, 실행 러너가 세션을 이어받으며, 중단되면 복구한다.
- 설계의 무게중심은 최종 산출물보다 작업 중간의 확인에 있다. 지식 기록에 따르면 공간 블록아웃에서 그레이박스, 아트, 조명, 오디오, 최적화로 넘어가는 단계마다 게이트가 있다.
- 성능 수치나 완성도 평가는 원천에서 확인하지 않았다. 아래 내용은 구조에 관한 설명이다.

### 구조와 패턴
- 에이전트 러너, 세션 재개와 재촉(nudge), 에디터 충돌 복구, MCP 상태 점검, 중복 실행을 막는 감독자. 장시간 작업을 유지하는 최소 구성요소가 한 저장소에 모여 있다.
- 뷰포트 캡처, 검사, 차이 비교를 자가 점검 수단으로 쓴다. 텍스트 로그가 아니라 산출 화면을 검증 입력으로 삼는 점이 특징이다.
- 작업 요구는 별도 프롬프트 문서로 분리되어 있다. 하네스 자체는 그대로 두고 목표만 바꿔 끼울 수 있는 구조다.
- 권리 구조가 층으로 나뉜다. 저장소 코드의 라이선스와 엔진, 플러그인, 모델, 텍스처, 음원의 이용 조건은 별개로 추적해야 한다.

### 적용 방법
- 가져올 것은 설치가 아니라 패턴이다. 러너의 재개 방식, 충돌 후 복구, 단계 게이트, 화면 기반 자가 점검을 추상화해 다른 도메인의 장기 작업 하네스 설계에 참조할 수 있다.
- 호환성을 먼저 본다. 지식 기록은 대상 엔진 에디터가 ARM64를 지원하지 않는다고 정리하고 있으므로, 설치 전에 무설치 정적 점검이나 드라이런으로 대상 호스트를 확인하는 순서가 맞다.
- 자산을 포함해 배포할 때는 파일별 출처·라이선스·저작자 표시 목록을 유지한다. 인증 정보는 기록에서 제외한다.

### 근거와 한계
- 원문 일부 확인: 저장소 주소가 다른 이름의 저장소로 리다이렉트되어, 현재 열린 페이지는 일반 장기 작업 도구를 소개하는 내용이었다. 이 카드의 개별 구성 설명은 특정 커밋(2026-08-14 기록) 기준 지식 기록에 의존했다.
- 상류 저장소의 현재 파일 구조와 지식 기록의 차이는 대조하지 않았다.
- 실행, 설치, 벤치마크 결과는 확인하지 않았다. 호환성 판단은 원천 기록의 인용이며 현재 호스트에서 검증하지 않았다.

## Hermes 관련성

agent의 장기 실행·도구 오류 복구·화면 기반 검증이 결합된 도메인별 사례다. Unreal 환경/호스트 호환성은 별도 검토 대상이며 일반 Hermes 사용자가 바로 실행 가능한 예제가 아닙니다.
