- 등록: 지식 reference 파일은 제한 검색에서 확인되지 않음.
- 활용: 증거 없음(unknown). 메모리 계층 설계 비교용 후보.

- 정리 근거: 원문 일부 확인
## 상세 정리

### 핵심 주장
- 각 세션은 새 컨텍스트 창으로 시작하므로, 세션 간 지식은 두 가지 메커니즘으로 전달된다고 설명한다. 하나는 사람이 쓰는 CLAUDE.md 지침이고, 다른 하나는 Claude가 교정과 선호를 바탕으로 스스로 적는 auto memory다.
- 두 메커니즘 모두 세션 시작 시 컨텍스트로 로드되지만 강제 설정이 아니라 참고 맥락으로 취급된다. 특정 행동을 확실히 막아야 한다면 지침 대신 PreToolUse 훅을 쓰라고 명시한다.
- 지침은 구체적이고 짧을수록 따라질 가능성이 높다는 것이 문서의 권고다. "2칸 들여쓰기"처럼 검증 가능한 문장을 예로 든다.

### 구조와 패턴
- 지침은 범위별로 계층화된다. 조직의 관리 정책, 사용자 전역(~/.claude), 프로젝트(저장소의 CLAUDE.md 또는 .claude/CLAUDE.md), 개인 로컬(CLAUDE.local.md, 보통 버전 관리에서 제외)의 순서로 설명된다. 상위 디렉터리의 파일은 실행 시 함께 로드되고, 하위 디렉터리의 파일은 해당 위치에서 작업할 때 로드된다.
- 긴 지침은 @경로 형식으로 다른 파일을 가져올 수 있다. 다만 가져온 파일도 실행 시 함께 로드되므로 컨텍스트 비용은 줄지 않는다. 가져오기는 최대 4단계까지 허용된다.
- 특정 파일 유형이나 디렉터리에만 적용할 규칙은 .claude/rules/ 아래에 두고 경로 조건을 붙여, 해당 파일을 다룰 때만 로드되게 한다.
- auto memory는 저장소 단위로 쌓이며 워크트리 사이에서 공유된다. 시작 시 앞부분 200줄 또는 25KB가 로드되고, /memory 명령으로 열어 읽거나 편집·삭제할 수 있다. 서브에이전트도 별도의 auto memory를 가질 수 있다고 한다.
- /compact 이후에도 프로젝트 루트의 CLAUDE.md는 디스크에서 다시 읽혀 주입된다. 반면 대화 중에만 준 지시는 사라질 수 있다고 경고한다.

### 적용 방법
문서가 권하는 운영 방식은 다음과 같다.
- 같은 실수를 두 번 하거나 같은 교정을 세션마다 반복하면 CLAUDE.md에 옮긴다. 여러 단계 절차나 일부 경로에만 필요한 내용은 스킬이나 경로 규칙으로 분리한다.
- /init으로 초안을 만들 수 있고, 기존 파일이 있으면 덮어쓰지 않고 개선안을 제안받는다.
- /doctor prompt-audit으로 오래된 지시, 없는 파일이나 명령에 대한 참조, 파일끼리의 모순을 점검한다. 감사 결과는 제안일 뿐이며 사용자가 적용을 요청해야 파일이 바뀐다.
- 저장소에 AGENTS.md만 있고 CLAUDE.md가 없으면 Claude가 AGENTS.md를 프로젝트 지침으로 읽는다. CLAUDE.md가 있으면 그것이 우선하며, CLAUDE.md 안에서 AGENTS.md를 가져오면 두 파일을 함께 쓸 수 있다.
- 지침이 실제로 로드됐는지는 /context나 /memory로 확인한다.

### 근거와 한계
- 공식 문서의 설명이므로 기능 동작은 문서 기준이다. 다만 AGENTS.md 직접 읽기처럼 버전 조건이 붙은 항목이 있어, 사용 환경의 버전에 따라 결과가 달라질 수 있다.
- "200줄 이하", "지시 준수율이 높아진다"는 권고는 문서의 가이드이며, 통제된 측정 결과로 제시되지 않는다.
- 이번 확인은 페이지 본문의 앞부분과 중간의 주요 절(지침 위치, 로드 방식, AGENTS.md, 트러블슈팅 일부)까지다. 나머지 부록은 읽지 않았다.
- 문서는 Claude Code의 동작만 설명하며 다른 도구의 메모리 구조와 비교하지 않는다.
- 지식 reference 등록은 확인되지 않았고, 사용자 메시지의 URL 근거만 있다.
