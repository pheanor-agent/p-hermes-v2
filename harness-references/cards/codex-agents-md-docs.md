- 정리 근거: 원문 일부 확인
## 상세 정리

### 핵심 주장
- Codex는 저장소의 지침을 AGENTS.md 파일로 받으며, 전역 지침, 프로젝트 지침, 하위 디렉터리의 재정의 지침을 정해진 우선순위로 쌓는다고 설명한다.
- 지침 체인은 실행할 때마다 다시 구성되므로, 별도의 캐시를 수동으로 지울 필요가 없다고 한다.
- 기본 파일명이 아닌 다른 이름의 지침 파일도 설정으로 등록하면 같은 방식으로 읽힌다고 설명한다.

### 구조와 패턴
- 디렉터리마다 검사 순서가 정해져 있다. 재정의 파일(AGENTS.override.md)이 가장 먼저 보이고, 그다음 AGENTS.md, 마지막으로 설정에 등록한 대체 파일명이 온다.
- 하위 디렉터리의 재정의 지침은 상위의 넓은 규칙을 대체한다. 그래서 특정 경로에서만 규칙을 달리 두는 구조를 만들 수 있다.
- 설정 파일에서 대체 파일명 목록과 지침의 최대 바이트 수(project_doc_max_bytes)를 지정하는 예가 있으며, 예시 값은 65536바이트다.
- 내용이 비어 있는 파일은 무시되며, 설정에 등록하지 않은 이름의 파일은 지침으로 인식되지 않는다.
- CODEX_HOME 환경 변수로 다른 홈 디렉터리를 지정하면 지침 체인과 설정을 프로필 단위로 분리할 수 있다. 자동화 전용 사용자를 두는 예가 제시된다.

### 적용 방법
문서가 제시한 확인 절차는 다음과 같다.
1. 저장소 루트에서 승인 없이 지침을 요약하게 실행해, 전역과 프로젝트 지침이 우선순위대로 반영되는지 본다.
2. 하위 디렉터리에서 실행해 중첩된 재정의 지침이 상위 규칙을 대체하는지 확인한다.
3. 로그 옵션으로 실제로 읽힌 지침 파일 목록을 남겨 감사한다.
4. 지침이 오래된 것 같으면 해당 디렉터리에서 새 세션을 시작한다.
문제 해결 항목으로는 파일이 전혀 읽히지 않을 때 작업 루트와 파일 내용을 확인하는 것, 예상과 다른 지침이 나오면 상위의 재정의 파일을 치우는 것, 대체 파일명 설정의 오타를 점검하는 것, 지침이 잘리면 바이트 상한을 올리거나 디렉터리를 나누는 것이 제시된다.

### 근거와 한계
- 공식 문서 페이지의 본문 앞부분과 설정·검증·문제 해결 절을 확인했다. 문서 중간의 일부 절과 하단 목록은 완전히 읽지 않았다.
- 우선순위와 설정 예시는 문서 기술이며, 버전이나 실행 환경에 따라 동작이 달라질 수 있다.
- 이 문서는 Codex의 동작을 설명하며, 다른 도구의 지침 파일(예: Claude Code의 CLAUDE.md)과의 호환 방식은 다루지 않는다.
- 대체 파일명 등록과 프로필 분리는 문서의 기능 설명만 확인했으며, 실제 실행으로 검증하지는 않았다.
- 지식 reference 등록은 확인되지 않았고, 사용자 메시지의 URL 근거만 있다.
