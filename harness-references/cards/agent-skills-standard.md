## 자체 요약

Agent Skills는 에이전트가 절차적 능력과 도메인 지식을 발견·로드할 수 있도록 디렉터리와 `SKILL.md` 중심으로 구성하는 portable format을 표방한다. 규격 본문과 구현별 지원 범위를 원문에서 구분해 확인해야 한다.

## 상세 정리

### 핵심 주장
- Agent Skills는 에이전트에게 절차적 능력과 전문 지식을 주기 위한 열린 형식이다. 핵심은 이름과 설명을 담은 메타데이터와 지시문이 들어 있는 `SKILL.md` 파일 하나를 기본 단위로 삼는 것이다.
- 형식의 목적은 이식성과 재사용이다. 한 번 만든 스킬을 호환되는 여러 에이전트 제품에서 쓸 수 있다고 소개한다.
- 규격 홈페이지는 형식의 개요만 설명하며, 세부 필드와 호환 요건은 별도 규격 문서에 있다.

### 구조와 패턴
- 스킬은 폴더 단위다. 필수 파일은 `SKILL.md`이고, 선택적으로 스크립트, 참고 자료, 템플릿, 기타 자원 폴더를 둘 수 있다.
- 로딩은 세 단계의 점진적 공개다. 시작 시에는 이름과 설명만 읽고, 과제와 맞으면 지시문 전체를 읽고, 실행 중에 필요한 파일이나 스크립트만 추가로 읽는다.
- 이 구조는 문맥 예산을 아끼면서 많은 스킬을 둘 수 있게 한다. 설명 문장이 자동 선택의 정확도를 좌우한다는 점이 함의된다.

### 적용 방법
- 스킬 설명은 짧고 구체적으로 쓰고, 세부 절차는 지시문과 참고 파일로 나눈다. 설명이 과제 판별의 유일한 입력이라는 전제에서 작성한다.
- 스킬을 여러 에이전트에서 공유하려면 형식 규격과 각 제품의 실제 로더 동작을 따로 검증한다. 규격 준수가 곧 해당 제품의 호환성을 보장하지 않는다.
- 스크립트를 포함하는 스킬은 실행 권한과 검토 절차를 정해 두어야 한다. 형식 자체는 안전 보증을 주지 않는다.
- 호환성 검토는 체크리스트로 한다: 필수 메타데이터가 있는지, 설명만으로 과제가 식별되는지, 지시문이 본문 길이 안에 들어가는지, 참조 파일 경로가 상대 경로로 유효한지를 확인한다.
- 긴 지시문은 본문에 전부 넣기보다 참고 파일로 분리하고, 본문에는 언제 그 파일을 읽을지만 적는다. 점진적 공개 구조를 그대로 살리는 방법이다.
- 여러 스킬이 같은 과제를 설명하면 자동 선택이 흔들린다. 설명 문장에 범위 경계를 명시해 중복을 줄인다.
- 스킬을 설계할 때 원천이 주장하는 세 단계 로딩을 전제로 하면, 설명 문장은 짧아도 되지만 과제 판별에 필요한 키워드는 빠지지 않아야 한다.

### 근거와 한계
- 원문 일부 확인: 개요 홈페이지만 열람했다. 규격 상세 문서(필드 정의, 검증 규칙)는 열지 않았으므로 필드 수준의 주장은 하지 않았다.
- 홈페이지의 클라이언트 목록과 지원 범위는 확인하지 않았다. 특정 제품에서 어떻게 동작하는지는 해당 제품의 공식 문서를 기준으로 봐야 한다.
- 이 형식이 Hermes의 스킬 로더와 같은 방식으로 해석되는지는 이 자료로 증명되지 않는다.

## Hermes 관련성

작업별 절차를 짧은 metadata와 필요 시 읽는 상세 자료로 나누는 discoverability를 비교하는 기준이다. Hermes의 skill 로더·runtime 호환성은 Hermes 자체 공식 문서로 검증해야 합니다.
